# Lint rules

- Rules live in `oxlint.config.ts` at the repo root, the Ren Oxlint plugin (`script/oxlint/ren/`) and `script/ast-grep/`. Oxlint loads its config and plugin through Node (see `.node-version`).
- Oxlint runs once for all packages, not once per package. `script/lint.ts` (the Turbo root task `//#lint:root`, or `bun script/lint.ts <paths>`) runs one type-aware `oxlint` over `packages` and `script`, then a second run without `--type-aware` over `oxlint.config.ts`, which belongs to no tsconfig. One process parses each big declaration file (Effect, `lib.dom`, `@types/node`) and each dependency's source once and shares it across the tsconfig programs: a full lint takes about half the wall time and 40% of the CPU of one run per package, with the same diagnostics. Oxlint maps each file to the nearest `tsconfig.json`, and `files` globs in `oxlint.config.ts` resolve from the config file, so nothing depends on the working directory. A package's own `lint` script still lints that package from its directory.
- tsrs, Oxlint's type-aware backend, reads a dependency's source, not its declarations in `node_modules/.ts-dist`, so lint needs no typecheck first.
- The Turbo cache is for the whole run: `//#lint:root` hashes every file git sees, so any source change lints everything again and an unchanged tree is a cache hit. `bun run check` skips Turbo for lint: `script/check.ts` passes the paths of the packages changed since `main` (and `script` when it changed) to one `script/lint.ts` run, and lints everything when `oxlint.config.ts`, `script/oxlint/**`, `tsconfig.base.json` or `bun.lock` changed.
- Resolve paths in `oxlint.config.ts` from the config file, not the working directory.
- The `site` package types come from `packages/site/.astro/types.d.ts`, which `astro sync` generates and git ignores. Without it every `astro:content` import is an `error` type and the type-aware rules report false positives. `script/lint.ts` runs `bun run --cwd packages/site sync` when the file is missing and `site` is in the paths; `astro check` (`typecheck`) regenerates it too. A package's own `lint` script does not sync.
- The root tools (ast-grep, knip, `oxfmt --check`) are Turbo root tasks (`//#lint:rules`, `//#lint:unused`, `//#format:check`) with explicit inputs, so a run with no relevant change is a cache hit.
- Every rule applies to every file. Overrides in `oxlint.config.ts` are by file type only, with four package-scoped exceptions: the Tailwind rules, which run only in the packages that use Tailwind (`app`, `ui`, `site`, `mobile`), because they visit every node and cost about 3 seconds of CPU in a package without a class list; the architecture blocks at the end; `packages/ui`, which drops the Tailwind restrictions and `react/only-export-components` that shadcn's components break (raw values, motion classes, `!important`, exported variants); and `packages/mobile`, which checks classes against its Uniwind entry (including `*ClassName` props), allows `role` on React Native views and default exports in Expo Router routes.
- Lint rules have no unit tests. The codebase is their test, so a new rule lands with fixes for everything it reports.
- Rules turned off on purpose:
  - `better-tailwindcss/enforce-canonical-classes`: it round-trips a worker per class list and took 6 to 8 seconds per package, 80% of the lint time of `ui` and `site`, for a stylistic hint.
  - `better-tailwindcss/enforce-shorthand-classes`: a stylistic hint (`w-4 h-4` to `size-4`) that took 2.4 seconds of CPU in `app`, 15% of its lint time.
  - The rules in `checkedByTypeScript`, for `.ts` and `.tsx` files: the compiler already reports them as errors (`noUnusedLocals` and `noUnusedParameters` for unused code), and every such file is in a tsconfig program except `oxlint.config.ts`, which keeps them. `.js` files keep them too, and so do `.astro` files, except that Oxlint does not report unused variables in `.astro` frontmatter. `eslint/no-unreachable` and `eslint/no-unused-labels` stay on, because without `allowUnreachableCode: false` and `allowUnusedLabels: false` the compiler only shows them as editor hints.
  - `oxc/no-barrel-file`: every module starts with `export * as X from "./x.js"`.
  - `unicorn/throw-new-error`: it misreads Effect's `Schema.TaggedError<X>()(...)`.
  - `typescript/only-throw-error`: TanStack Router throws `redirect()`.
  - `unicorn/prefer-global-this`: `globalThis.x` would bypass the `window.x` restrictions.
  - `eslint/no-useless-return`: it conflicts with `noImplicitReturns`.
  - `eslint/require-yield`: `Effect.fn` takes generators that may not yield.
  - `noPropertyAccessFromIndexSignature`: `noUncheckedIndexedAccess` already types index access as possibly `undefined`.
