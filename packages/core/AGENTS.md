# @ren/core

- One module per domain. Each exports `Interface`, `Service` (`Context.Service`, keyed `@ren/core/<Name>`) and `layer`. A service with distinct implementations per provider exports `layer<Provider>` instead. `Brains` is the host-neutral brain service (start, send, access, tokens, pull, models, environments; every start is a durable `StartRun`); `BrainHost` is the only host seam, with `layerCell` (celld and Cloudflare, on `CELL_URL`) and `layerSandbox` (`BrainLifecycle` on the deployment's brain provider, `BrainProvider.Registry`; a brain keeps the provider it was made on). `MachineLifecycle.make` is the managed machine's state machine (phases in `Machine.Phase`); a kind of machine gives it its table, its ready check, its wake call and its `desiredSetup` (a template's image and the host list from `EnvironmentNetwork`); at a wake, a machine on another image takes its provider's `stepsBetween` in place or is replaced. `MachineAccess.Interface` is what a caller asks of one machine; `BrainLifecycle` meets it. `Bundles` holds the current version of each of Ren's bundles for machines (`dependencies`, `brain`, `executor`; built by `brain-runtime/machine/bundle.ts` into the server image at `REN_BUNDLES`), moves it only to a later build, and signs the token a machine downloads one with. `Brains` checks a message's inline files against `Session.inlineLimitOf` and gets each brain's models from `Models.Service`; `Models.layerNone` grants no endpoints until a model source lands. `EnvironmentTemplates.Service` is the environment primitive: an organization's saved config for one environment provider, with its `networking`. A changed config gets the next `config_version` and a durable build run (`BuildRun`), one at a time per template; a result counts only while the template still has that version. A provider with a `build` step makes the image (E2B: one E2B template per Ren template, a tag per config); one without is `ready` at once. A space picks its hand in `space.hand` (`Space.Hand`: co-located, remote with a template, or none; `Space.update` refuses a hand that its brain provider cannot run), and `SessionRunner.create` puts it in the chat's `Session.StartInput`. `MachineProvider` is the one contract for brain and environment providers (`MachineProvider.make`, one per kind, in `machine-provider/`: `e2b` and `local` make brains, `e2b` and `docker` make environments). Each has a config schema that both checks the config and gives the form its JSON Schema; a step that a provider does not have does nothing. `EnvironmentProvider.Registry` is the deployment's list of environment providers. `ProviderCheck.run` stops the server at start when a brain or a template names a provider that is not registered. A provider's `create` gets the machine's labels and variables (for an environment, the executor's `ExecutorVariables`, from `@ren/environment-api`) and sets the variables on the machine as they are; an environment provider's `connect` returns a URL where an executor answers (`MachineProvider.waitForExecutor`). `create` is idempotent per machine id and generation: two calls give one machine, because Ren creates outside a transaction and may ask twice. A remote hand's machine runs on `MachineLifecycle` like a brain's (kind `hand`, ready when its provider says the executor answers); a brain that could not reach it asks with `unreachable`, and Ren checks the machine first. `Environments.Service` binds a session to an environment in `session_environment`, and at the first tool call gives it an environment: one with room (`sessions_per_environment`, idle sessions not counted), or a new one the provider provisions. `release` marks a session idle (`idle_at`): it keeps its environment, and its next access clears the mark. It signs environment tokens with `ENVIRONMENT_KEYS` for `ENVIRONMENT_TOKEN_LIFETIME`.
- Name service methods with `Effect.fn("<Name>.<method>")`.
- Re-export schema values from `@ren/schema` instead of redefining them.
- Core never imports `@ren/protocol` or `@ren/server`, and never knows about Ren's own HTTP API. It calls outside services through `HttpClient` (`Mailer`), and session hosts through `@ren/host-api` (`BrainHost`).
- Tests use `testEffect(layer)` from `@ren/core/testing`. Use `it.live` for real time, the filesystem, child processes or the database.
- Tests run through `script/test.ts` at the repo root, with a temporary HOME and without credential env vars.
- A primitive service's `Interface` extends `Primitive.Interface<typeof <Name>.definition>`. Methods take the caller's `Actor.Info` first.
- Primitive methods use the error types declared by `Primitive.Interface`: `NotFound`, `Forbidden`, `Conflict`, and `Invalid` for create and update validation. A record the actor cannot see is `NotFound`.
