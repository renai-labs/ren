# @ren/core

- One module per domain. Each exports `Interface`, `Service` (`Context.Service`, keyed `@ren/core/<Name>`) and `layer`. A service with distinct implementations per provider exports `layer<Provider>` instead. `Brains` is the host-neutral brain service (start, send, access, tokens, pull, models, environments; every start is a durable `StartRun`); `BrainHost` is the only host seam, with `layerCell` (celld and Cloudflare, on `CELL_URL`) and `layerSandbox` (`BrainLifecycle` on a `SandboxProvider`). `Brains` reads `BRAIN_MAX_FILE_SIZE` and gets each brain's models from `Models.Service`; `Models.layer` takes the deployment's model providers (`Models.Provider`, one endpoint and a key per brain each; `ren-inference/provider.ts` is Ren's) and only aggregates them; `Models.layerNone` registers none. `EnvironmentTemplates.Service` is the environment primitive: an organization's saved config for one environment provider, which spaces link through `SpaceEnvironmentTemplate`. `EnvironmentProvider.Registry` is the deployment's list of environment providers (`EnvironmentProvider.make`, one per kind; `environment-provider/docker.ts` is the first), each with a config schema that both checks the config and gives the form its JSON Schema. A provider's `provision` gets the executor's variables (`ExecutorVariables`, from `@ren/hand-api`) and sets them on the machine as they are; `connect` returns a URL where an executor answers (`EnvironmentProvider.waitForExecutor`). `provision` is idempotent per environment id: two calls for one environment give one machine, because Ren provisions outside a transaction and may ask twice. `connect` fails with `Gone` when the machine no longer exists; Ren then gives the environment's sessions a new environment and the next generation. `Environments.Service` binds a session to an environment in `session_environment`, and at the first tool call gives it an environment: one with room (`sessions_per_environment`, idle sessions not counted), or a new one the provider provisions. `release` marks a session idle (`idle_at`): it keeps its environment, and its next access clears the mark. It signs environment tokens with `ENVIRONMENT_KEYS` for `ENVIRONMENT_TOKEN_LIFETIME`.
- Name service methods with `Effect.fn("<Name>.<method>")`.
- `Artifacts.Service` owns artifacts: one row each, keyed by the harness's id, with code archives as `.tar.gz` objects in the drive bucket (`ObjectStorage`, which `Drives` also uses). It runs them on the one `ArtifactProvider.Service` the composition root provides: `ArtifactWorkerd.layer` runs `wrangler dev` on Ren's machine. A provider's `deploy` returns once the deployment serves and returns its `binding`. `stop` removes only the deployment, retaining the row, code archives, config and application data.
- Artifact source bytes never pass through Ren: `upload` signs a PUT URL for one archive, and `archive` signs a GET URL of the last published one. `deploy` checks the named upload with `ArtifactArchive.read` (limits, paths, entry, `ren-artifact.json`), copies the version it checked to an immutable code archive, then claims `active_deployment_id` and durably queues `ArtifactDeploy` and `ArtifactSettle` in the same SQL transaction. It returns before provider readiness. Workflows own pending config, archive and title, and deployment results/errors; the artifact row retains the last successful code/config (or the initial attempted source before its first success). `status` queries a specific deployment workflow after checking ownership. `ArtifactStop` takes its own active UUID claim and durably fences new deployments, interrupts and settles active deployment work, then stops the provider. Public `stop` waits for cleanup and claim settlement, including an already pending stop. `ArtifactSettle` clears each claim only after its workflow's terminal result is persisted, including failed deployments and stops. A completed deployment never remains as the active pointer. Callers provide `DurableRunner.layerEffect` with the same SQL client as `Database.Service`; the in-memory workflow engine does not provide these durability guarantees.
- Re-export schema values from `@ren/schema` instead of redefining them.
- Core never imports `@ren/protocol` or `@ren/server`, and never knows about Ren's own HTTP API. It calls outside services through `HttpClient` (`Mailer`), and session hosts through `@ren/host-api` (`BrainHost`).
- Tests use `testEffect(layer)` from `@ren/core/testing`. Use `it.live` for real time, the filesystem, child processes or the database.
- Tests run through `script/test.ts` at the repo root, with a temporary HOME and without credential env vars.
- A primitive service's `Interface` extends `Primitive.Interface<typeof <Name>.definition>`. Methods take the caller's `Actor.Info` first.
- Primitive methods use the error types declared by `Primitive.Interface`: `NotFound`, `Forbidden`, `Conflict`, and `Invalid` for create and update validation. A record the actor cannot see is `NotFound`.
