# @ren/db

- Tables live in `src/<domain>.sql.ts`. Use snake_case object keys and never pass column names as strings (`org_id: text()`, not `orgID: text("org_id")`). ast-grep enforces this. The exception is `src/auth.sql.ts`, generated by the Better Auth CLI; never edit it, regenerate it with `bun run generate` from the repo root.
- Generate migrations with drizzle-kit (`bun run db generate`). Never edit generated migrations.
- Access Postgres through `Database.Service` (Drizzle) or `SqlClient.SqlClient`. Do not create ad hoc connections. `AuthDatabase.Service` exists only for Better Auth, which needs Promise-based Drizzle.
- Tests use `Testing.layer`, which clones a migrated template into a fresh database and drops the clone when the layer's scope closes. Templates are cached by migration contents, the lockfile, database role and template recipe. They reject connections and contain no test data. Each clone's owner holds a Postgres advisory lock on it; the first fixture in a process drops `ren_test_clone_*` databases whose lock is free, so a killed run's databases are removed by the next run. Never point tests at a shared database. Start Postgres with `docker compose up -d` from the repo root.
- Drizzle's `execute` is typed as an array but returns `{ rows }` at runtime in the current RC. Prefer query builders or `SqlClient` for raw SQL.
