An automation runs an agent in a [space](/docs/spaces/) without you. It has instructions, an agent and one trigger: a **Schedule**, which runs it at set times, or a **Webhook**, which runs it when another app sends a request.

<Screenshot
  shot="automations/schedules"

  caption="Automations, with the schedules of every space."
/>

**Automations** in the sidebar lists the automations of all your spaces, on a **Schedules** tab and a **Webhooks** tab. Each space also has its own **Automations** page.

## Create an automation

1. Select **New automation**, and pick the space.
2. Name it, and write the instructions: what the agent should do each time it runs.
3. Pick the agent. Without one, Ren runs it with the space's settings.
4. Select **Add trigger** and pick **Schedule** or **Webhook**. **From an app** turns on a webhook that one of the space's [apps](/docs/apps/) offers, with its instructions already written.
5. Select **Save**, then **Test** to run it once now.

Use the switch in the header to turn it on or off. **Duplicate** and **Delete** are in `⋯`. Deleting an automation stops its trigger. The chats it started stay.

## Schedules

Pick how often it runs: **Hourly**, **Daily**, **Weekdays**, **Weekly**, **Monthly**, **Once** on a date, or **Custom (cron)**.

Under **Advanced**, set the time zone, which starts as yours from **Settings → Preferences**, and an end date. Each run starts a new chat.

A space can have 50 active schedules, each at least 5 minutes apart.

## Webhooks

A webhook is a URL that another app sends requests to, such as Stripe on a failed payment or Linear on a new issue. Each request it accepts starts or continues a chat.

### Set up a webhook

1. Save the automation to get its URL, then select **Requests, filter and signature**.
2. Copy the URL into the other app. It holds a token, so treat it like a password.
3. If the other app signs its requests, set the [signature](#signature).
4. Send a test event from the other app. It shows under **Requests**.
5. Switch it from **Debug** to **Live**. **Debug** only records requests. **Live** runs the agent on them.

### Signature

Pick the check that the other app supports:

| Check                        | Use it for                                |
| ---------------------------- | ----------------------------------------- |
| **URL only**                 | Apps that cannot sign requests            |
| **Header equals the secret** | Apps that send a fixed secret in a header |
| **HMAC of the body**         | Apps that sign the body, such as GitHub   |
| **Standard Webhooks**        | Svix, Clerk, Resend                       |
| **Stripe**                   | Stripe                                    |

Select **Set secret**. Ren makes a secret and shows it once, or you paste the one the other app gave you. **Live** stays off until the secret is set.

### Which requests run the agent

| Setting                      | What it does                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------- |
| **Start a session when**     | A condition, such as "the action is create". Other requests are ignored.      |
| **Session continuation key** | A value, such as an issue ID. Requests with the same value continue one chat. |
| **Event identifier**         | A delivery ID. Ren skips a request it has already seen.                       |
| **Session title**            | A value that names the chat, such as the issue title.                         |

To set one, open a recorded request, select a value in its body, and pick what to use it for. Then select **Save**. **Check** tests the rules on the last 20 requests.

### Requests

The webhook lists its requests from the last 30 days, with their outcome:

| Outcome   | Meaning                                          |
| --------- | ------------------------------------------------ |
| Queued    | Waiting to run.                                  |
| Started   | It started a chat.                               |
| Continued | It continued a chat.                             |
| Recorded  | Kept without a run: the webhook is in **Debug**. |
| Ignored   | The condition was false.                         |
| Duplicate | Ren saw its event identifier before.             |
| Rejected  | Wrong or missing signature, or a body over 1 MB. |
| Throttled | Over 60 requests in one minute.                  |
| Failed    | The agent could not take it.                     |
| Answered  | A URL check from the other app.                  |

Select **Replay** to run the queued, recorded, throttled and failed requests. The webhook must be **Live**.

When the URL leaks, select **Rotate URL** and paste the new one in the other app.

## Run history

Select **Run history** on an automation to see each run from the last 30 days. Select a run to open its chat beside the list, and reply to continue it.

## Needs attention

Ren stops an automation and marks it **Needs attention** when it cannot run as set up:

| Cause                                         | Fix                                      |
| --------------------------------------------- | ---------------------------------------- |
| Its owner left the space                      | Save it to run it as you                 |
| Its agent left the space                      | Pick another agent                       |
| The last 5 runs failed                        | Open the failed runs, fix it, turn it on |
| A webhook's rule broke on 5 requests in a row | Fix the rule, then turn it **Live**      |
| The app no longer offers the webhook          | Delete it                                |

## Who an automation runs as

An automation runs as its owner: the last person who changed what it does, such as its instructions, agent, schedule or rules. Any member of the space can manage its automations.

For a webhook, **If the owner leaves the space** under **Advanced** decides what happens: **Switch it to Debug**, **Run it as me**, or run it as another member.

A chat from an automation has nobody to approve a permission card, so actions that ask first are denied. Allow what it needs in [permissions](/docs/permissions/).
