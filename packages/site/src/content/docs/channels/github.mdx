## Connect GitHub

<Steps>

1. Open **Settings → Channels → GitHub**.

2. Select **Connect GitHub**, approve Ren on your GitHub organization, and choose the repositories Ren can see.

</Steps>

Then [link each repository to a space](/docs/channels/#link-a-place-to-a-space). To add a repository later, give the Ren app access to it on GitHub.

Any member can connect GitHub. That person becomes the fallback user of private repositories that are not linked.

## Mentions

A mention counts in:

- a new comment, or a comment that you edit to add `@renagent`,
- the title or description of an issue or pull request, when you open, edit or reopen it.

A mention in a review comment on a line continues the chat of the pull request, and Ren replies to that comment. Ren ignores a mention in the summary of a review, and mentions from bots.

When Ren creates a task in a chat that started on an issue or a pull request, it links the task to it.

## Where Ren works

| Message from                                              | Space                 |
| --------------------------------------------------------- | --------------------- |
| An issue or pull request linked to a [task](/docs/tasks/) | The space of the task |
| A linked repository                                       | The linked space      |
| Any other repository                                      | **General Space**     |

## Who Ren runs as

Ren matches the sender by the GitHub account they signed in to Ren with, or by the public email on their GitHub profile. When it cannot, it uses the [fallback user](/docs/channels/#who-ren-runs-as):

| Message from                              | Fallback user                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------------- |
| A linked repository                       | The person in **Run unknown senders as**. For a public repository, it starts as **Nobody**. |
| Any other private repository              | The person who connected GitHub                                                             |
| Any other public repository               | None: only Ren members                                                                      |
| An issue or pull request linked to a task | None: only Ren members                                                                      |

## Review pull requests

On a linked repository, select `✎` and turn on **Review pull requests when ready**. Ren reviews each pull request when it is opened, or when it is marked ready for review. It does not review drafts, new pushes, or pull requests that a bot opened.

## Link pull requests to tasks

Write a task's number, such as `REN-12`, or paste its link in the title or description of an issue or a pull request, or in the branch name, such as `ren-12-fix-login`. Ren links it to that [task](/docs/tasks/) and posts a card with the task's title and status. Words such as `Fixes` and `Closes` change nothing.

When a linked pull request is merged, Ren marks its open tasks as done.

## GitHub in chats

Chats can use `git` and the `gh` command on GitHub when your organization connected GitHub, or when you signed in to Ren with GitHub.

| Space          | Ren uses             | Commits and pull requests show as |
| -------------- | -------------------- | --------------------------------- |
| Personal space | Your GitHub sign-in  | You                               |
| Shared space   | The Ren app's access | `renagent[bot]`                   |

To have a space work on a repository, add it on the space's [Repositories](/docs/repositories/) page.
