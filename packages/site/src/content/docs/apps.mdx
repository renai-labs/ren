An app connects Ren to a service like Gmail, Linear, HubSpot, or Shopify. For example, Gmail lets Ren read, summarize, and draft email.

```text
@Gmail summarize my unread email from today.
```

## How apps work

An app gives Ren tools through one or more MCP servers. It can also include [skills](/docs/apps/#skills) that explain how to use those tools. You connect the account or key that the app needs.

Add an app to a [space](/docs/spaces/) to make it available in every chat of that space. An **account** holds the sign-ins and keys of an app. Several spaces can use the same account.

| Part                       | What it does                           | Linear example                  |
| -------------------------- | -------------------------------------- | ------------------------------- |
| App                        | Gives Ren tools                        | Reads and updates issues        |
| [Channel](/docs/channels/) | Receives requests and delivers replies | Receives issues assigned to Ren |

There are two kinds of app:

| Kind            | Who makes it                             | Who can edit it                  |
| --------------- | ---------------------------------------- | -------------------------------- |
| Ren's registry  | Ren                                      | Nobody. Ren keeps it up to date. |
| Your org's apps | Someone in your organization, in a space | The members of that space        |

If no app exists for a service, [create one](#create-an-app) from its MCP server, your skills, or both.

## Create an app

Create an app when the service you need is not in the list. An app you create can hold MCP servers, skills, or both.

<SurfaceTabs>
<Fragment slot="app">

<Steps>

1. Open **Apps** and select **Create app**. In a space's **Add app** dialog, select **Create app** under the list.
2. Paste the address of an MCP server, such as `https://mcp.acme.dev/mcp`. Ren reads the server and fills in its sign-in, name, description, and icon. You can change each of them.
3. To add skills, drop their folders on the dialog, select **Choose folder**, or select **From GitHub** and paste the link to a skill folder.
4. Under **Add to**, pick the space that owns the app.
5. Select **Create app**. If the server uses a sign-in, the button is **Create and sign in**: Ren creates the app and opens the sign-in window.

</Steps>

Ren adds the app to its space with a first account, and opens the app's page. A key or token that you typed in the dialog goes into that account, never into the app itself. For the details of MCP servers and their sign-ins, see [Custom MCPs](/docs/apps/#custom-mcps). For skill folders, see [Skills](/docs/apps/#skills).

### Spec mode

Select **Spec** at the top of the dialog to see the app as YAML. You can paste YAML or JSON there too. Ren checks it as you type, and shows each problem with the field it belongs to, such as `mcps.acme.auth`. **Form** and **Spec** edit the same app, so you can switch back and forth.

Webhooks are edited in Spec mode only.

### Advanced

**Advanced**, under the name, holds settings that most apps do not need:

| Setting        | What it does                                                         |
| -------------- | -------------------------------------------------------------------- |
| Packages       | apt, npm, pip, and Go packages that Ren installs for the app         |
| Build commands | Commands that run after the packages, one per line                   |
| Depends on     | Other apps of your organization that this app needs                  |
| Secrets        | Env names, such as `ACME_API_KEY`, that each account fills in        |
| MCP timeouts   | How long Ren waits for each MCP server to start, list tools, and run |

## Edit, move, or archive an app

Members of the space that owns an app can change it. Open the app from **Apps**:

- Select **Edit** to open the same dialog. Change what you need, then select **Save**. If someone else saved the app since you opened it, Ren shows **The app changed. Reload before saving.** Select **Reload** to start again from the saved app.
- Select **⋯ → Move to another space** to make another space its owner.
- Select **⋯ → Archive app** to remove it from every space that uses it.

## Use an app in a chat

Type `@` in the composer and pick the app. The mention tells Ren which app to use for that request:

```text
@Gmail summarize my unread email from today.
```

Mentions are optional. Mention an app when more than one service can do the request. If the space does not have the app, Ren shows a connect card to add it.

## Remove an app from a space

Open the space, then **Apps**. Open the row menu of the app and select **Remove from** the space. Accounts that have a sign-in stay in **Settings → Credentials**.

## Troubleshooting

### The sign-in page does not load

Some apps, such as Figma, Meta Ads, and Shopify, end the sign-in on a page that does not load. This is expected.

1. Copy the full address of that page from the browser.
2. Paste it into **Paste the address from the sign-in tab** on the card.
3. Select **Finish**.

### The connect card does not work in a channel

Connect cards work only in the web app, not in channels. Connect the account from a chat in the web app.

### “Couldn’t reach the server” when you create an app

Ren could not read the MCP server at that address. Check the address. You can still create the app, and connect it later.

## Skills

A skill is a reusable set of instructions for a type of task. Its folder contains `SKILL.md` and optional supporting files, such as templates or scripts. Ren reads the description in every chat, but loads the full instructions only when the request needs them.

This example `SKILL.md` is for release notes:

```md
---
name: release-notes
description: Write release notes from merged pull requests. Use when asked for release notes or a changelog.
---

Group changes under Features, Fixes, and Internal.
Link each item to its pull request.
Skip dependency bumps unless they fix a security issue.
```

### Skill or instructions

| Use                                              | For                                                                                     | When Ren reads it       |
| ------------------------------------------------ | --------------------------------------------------------------------------------------- | ----------------------- |
| Project [instructions](/docs/concepts/projects/) | Rules for every chat in a project, such as tone or which repository to work in          | On every turn           |
| A skill                                          | A procedure that only some requests need, or a procedure that you want in many projects | When a request needs it |
| The chat prompt                                  | A one-off request                                                                       | In that chat            |

If you paste the same steps again and again, make them a skill.

### Write a skill

`SKILL.md` starts with frontmatter between two `---` lines. Ren checks it with the [Agent Skills](https://agentskills.io) rules:

| Field                                  | Rule                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `name`                                 | Required. Up to 64 characters: lowercase letters, digits, and single hyphens. It must equal the folder name. |
| `description`                          | Required. Up to 1,024 characters that say when to use the skill                                              |
| `compatibility`                        | Optional. Up to 500 characters                                                                               |
| `license`, `allowed-tools`, `metadata` | Optional                                                                                                     |

No other fields are allowed. Every other file in the folder must be text in UTF-8, such as Markdown, scripts, or templates.

If the skill needs a key, list its env name under `metadata.requiredCredentials`. Each account of the app then asks for its value:

```md
---
name: release-notes
description: Write release notes from merged pull requests.
metadata:
  requiredCredentials:
    - kind: env
      name: GITHUB_TOKEN
---
```

### Add skills to an app

A skill reaches a space through an [app](/docs/apps/). An app can hold only skills, or skills with the MCP servers whose tools they explain.

3. To use a skill that lives on GitHub, select **From GitHub** and paste the link to its folder, such as `https://github.com/acme/skills/tree/main/release-notes`.
4. With no MCP server, the app takes the name and description of the first skill. Change them if you like.
5. Pick the space under **Add to**, and select **Create app**.

### Sources

| Source   | How it works                                                                                                          | Use it for                 |
| -------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| A folder | You drop or choose a folder. Ren stores a copy of its files in the app.                                               | Skills you write yourself  |
| GitHub   | You paste the link to a folder. Ren fetches the files from the repository, at the branch, tag, or commit in the link. | Skills you maintain in git |

A skill from a branch follows that branch: new commits change the skill without an edit of the app. Link to a commit to fix its content.

### Edit or remove a skill

Open the app that holds the skill and select **Edit**. To change a skill, drop its folder again. To remove it, select its trash icon. Then select **Save**. Spaces that use the app get the change in their next chat.

To take a skill out of every space, remove it from its app, or archive the app.

### Troubleshooting

#### Two skills have the same name or similar instructions

If two apps in a space have skills with the same `name`, Ren loads only the skill of the app that your organization added first. Skills with different names but similar instructions both load. Ren then picks one by its description. Fix: make each description say when to use that skill.

### Good to know

- Only members of the space that owns an app can change its skills.
- To see the skills of an app as YAML, with their files, select **Spec** in the dialog.

## Custom MCPs

A custom MCP connects Ren to a server that no [app](/docs/apps/) covers yet. MCP is a protocol that gives agents access to tools. For example, an internal documentation server can give search tools to every chat of a space.

You add a custom MCP by creating an app for it. The app can hold more than one MCP server, and [skills](/docs/apps/#skills) that explain how to use their tools.

### Remote and local servers

| Kind       | What you paste                                     | Example                                      |
| ---------- | -------------------------------------------------- | -------------------------------------------- |
| **Remote** | The address of a server that Ren reaches over HTTP | `https://mcp.acme.dev/mcp`                   |
| **Local**  | A command that runs on the machine of the space    | `npx -y @modelcontextprotocol/server-github` |

Ren reads a remote server as soon as you paste its address. It finds how the server signs in, its name, description, and icon, and the tools that it lists without a sign-in. A local server starts only in a chat, so Ren does not read it first.

### Add an MCP server

<SurfaceTabs>

2. Paste the server's address or command. For an address, wait for **Checking…** to end. Ren shows the server's name and the number of tools that it found.
3. Check **Auth**. Ren picks it from the server; you can change it.
4. For a local server, add its **Env** values and the names of its **Secrets**.
5. To add a second server, select **Add MCP server**.
6. Pick the space under **Add to**, then select **Create app** or **Create and sign in**.

</Steps>

Select **More** on a server to change its scopes, client ID, name, or description.

### Authentication

For a remote server, choose how Ren signs in:

| Auth         | What you give                                                         |
| ------------ | --------------------------------------------------------------------- |
| No Auth      | Nothing. Use this for public servers.                                 |
| OAuth 2.0    | A sign-in on the provider's page. **Create and sign in** opens it.    |
| Bearer Token | A token that Ren sends as `Authorization: Bearer …` (coming soon)     |
| API Key      | A key that Ren sends in the header that you name, such as `X-API-Key` |
| Basic Auth   | A user name and password (not supported for now)                      |

A key or token that you type in the dialog goes into the app's first account in its space. It never becomes part of the app, so anyone who reads or edits the app does not see it.

A local server's **Env** values are part of the app, and everyone who can see the app can read them. Put a key in **Secrets** instead: each account asks for its value when you connect it.

### Tools

The app's page lists the tools of each remote server. Some servers list their tools only after a sign-in; the page then shows **Tools show after you sign in.** A local server shows **Tools show after the first chat.**

### Connect its credentials

If the server needs a credential that you did not type when you created the app, connect it from the app's page or from the card that Ren shows in a chat. See [Apps](/docs/apps/#connect-an-account) and [Credentials](/docs/credentials/).

### Good to know

- Only members of the space that owns the app can edit, move, or archive it.
- To see or paste the whole app as YAML or JSON, select **Spec** in the dialog. See [Spec mode](/docs/apps/#spec-mode).
