An app connects Ren to a service like Gmail, Linear, HubSpot, or Shopify. For example, Gmail lets Ren read, summarize, and draft email.

```text
@Gmail summarize my unread email from today.
```

## How apps work

An app gives Ren tools through one or more MCP servers. It can also include [skills](/docs/concepts/skills/) that explain how to use those tools. You connect the account or key that the app needs.

Add an app to a [space](/docs/concepts/spaces/) to make it available in every chat of that space. An **account** holds the sign-ins and keys of an app. Several spaces can use the same account.

| Part                                | What it does                           | Linear example                  |
| ----------------------------------- | -------------------------------------- | ------------------------------- |
| App                                 | Gives Ren tools                        | Reads and updates issues        |
| [Channel](/docs/concepts/channels/) | Receives requests and delivers replies | Receives issues assigned to Ren |

There are two kinds of app:

| Kind            | Who makes it                             | Who can edit it                  |
| --------------- | ---------------------------------------- | -------------------------------- |
| Ren's registry  | Ren                                      | Nobody. Ren keeps it up to date. |
| Your org's apps | Someone in your organization, in a space | The members of that space        |

If no app exists for a service, [create one](#create-an-app) from its MCP server, your skills, or both.

## Create an app

Create an app when the service you need is not in the list. An app you create can hold MCP servers, skills, or both.

<SurfaceTabs>
<Fragment slot="app">

<Steps>

1. Open **Apps** and select **Create app**. In a space's **Add app** dialog, select **Create app** under the list.
2. Paste the address of an MCP server, such as `https://mcp.acme.dev/mcp`. Ren reads the server and fills in its sign-in, name, description, and icon. You can change each of them.
3. To add skills, drop their folders on the dialog, select **Choose folder**, or select **From GitHub** and paste the link to a skill folder.
4. Under **Add to**, pick the space that owns the app.
5. Select **Create app**. If the server uses a sign-in, the button is **Create and sign in**: Ren creates the app and opens the sign-in window.

</Steps>

Ren adds the app to its space with a first account, and opens the app's page. A key or token that you typed in the dialog goes into that account, never into the app itself. For the details of MCP servers and their sign-ins, see [Custom MCPs](/docs/concepts/custom-mcps/). For skill folders, see [Skills](/docs/concepts/skills/).

### Spec mode

Select **Spec** at the top of the dialog to see the app as YAML. You can paste YAML or JSON there too. Ren checks it as you type, and shows each problem with the field it belongs to, such as `mcps.acme.auth`. **Form** and **Spec** edit the same app, so you can switch back and forth.

Webhooks are edited in Spec mode only.

### Advanced

**Advanced**, under the name, holds settings that most apps do not need:

| Setting        | What it does                                                         |
| -------------- | -------------------------------------------------------------------- |
| Packages       | apt, npm, pip, and Go packages that Ren installs for the app         |
| Build commands | Commands that run after the packages, one per line                   |
| Depends on     | Other apps of your organization that this app needs                  |
| Secrets        | Env names, such as `ACME_API_KEY`, that each account fills in        |
| MCP timeouts   | How long Ren waits for each MCP server to start, list tools, and run |

## Edit, move, or archive an app

Members of the space that owns an app can change it. Open the app from **Apps**:

- Select **Edit** to open the same dialog. Change what you need, then select **Save**. If someone else saved the app since you opened it, Ren shows **The app changed. Reload before saving.** Select **Reload** to start again from the saved app.
- Select **⋯ → Move to another space** to make another space its owner.
- Select **⋯ → Archive app** to remove it from every space that uses it.

## Connect an account

When Ren needs an app that is not connected, it shows a connect card in the chat. If the app is not in the space yet, a connection from the card also adds it.

<Fragment slot="app">

2. Sign in to the account that you want Ren to use, or enter the key that the app asks for.
3. Go back to Ren. The card shows **Connected**, and Ren continues.

## Use an app in a chat

Type `@` in the composer and pick the app. The mention tells Ren which app to use for that request:

```text
@Gmail summarize my unread email from today.
```

Mentions are optional. Mention an app when more than one service can do the request. If the space does not have the app, Ren shows a connect card to add it.

## Remove an app from a space

Open the space, then **Apps**. Open the row menu of the app and select **Remove from** the space. Accounts that have a sign-in stay in **Settings → Credentials**.

## Troubleshooting

### The sign-in page does not load

Some apps, such as Figma, Meta Ads, and Shopify, end the sign-in on a page that does not load. This is expected.

1. Copy the full address of that page from the browser.
2. Paste it into **Paste the address from the sign-in tab** on the card.
3. Select **Finish**.

### The connect card does not work in a channel

Connect cards work only in the web app, not in channels. Connect the account from a chat in the web app.

### “Couldn’t reach the server” when you create an app

Ren could not read the MCP server at that address. Check the address. You can still create the app, and connect it later.
