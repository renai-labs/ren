A credential is an account or a secret that Ren uses to work in another service. Examples are a Gmail connection, a Stripe API key, and a `DATABASE_URL` for a script. Ren encrypts each credential and gives it only to the tools that need it.

<AskRen prompt="Store my OpenWeather API key as OPENWEATHER_API_KEY for this space." />

## Levels

Each credential belongs to one level. Choose the level by who must be able to use it.

| Level        | Who can use it                                                       | Use it for                                     |
| ------------ | -------------------------------------------------------------------- | ---------------------------------------------- |
| Organization | Every chat in the organization                                       | Accounts that all spaces share, such as Notion |
| Space        | Chats in the projects of the space, and its members' personal spaces | The accounts of one team or one client         |
| Personal     | Only chats in your personal space                                    | Your own accounts, such as your inbox          |

Only the members of a space can see its credentials. An organization admin who is not a member cannot see or use them. Only you can see your personal credentials.

An agency can keep the accounts of each client in the space for that client. Then only the team for that client can use them.

### Which credential Ren uses

Ren uses the first credential that matches, in this order:

| Where the chat runs | Order Ren checks                                                                         |
| ------------------- | ---------------------------------------------------------------------------------------- |
| A shared space      | The space, then the organization                                                         |
| Your personal space | Your personal credentials, then your shared spaces (oldest first), then the organization |

A chat from a channel, a schedule, or a task uses the order for the space of its project. The person who sent the message does not change the order.

## Types

| Type       | What it holds                                                         | Where you add it                                        |
| ---------- | --------------------------------------------------------------------- | ------------------------------------------------------- |
| App        | A signed-in account, such as Gmail or GitHub                          | Sign in when you [connect an app](/docs/concepts/apps/) |
| Token      | An API token for an app or a custom MCP                               | Paste it when you connect the app or the custom MCP     |
| Password   | A username and a password                                             | Type them when you connect the app or the custom MCP    |
| Secret     | A value that Ren reads as an environment variable, such as `$API_KEY` | **Add credential** on the Credentials page              |
| Custom MCP | The fields that a [custom MCP](/docs/concepts/custom-mcps/) asks for  | Type them when you connect the custom MCP               |

## Add a secret

<Steps>

1. Open **Settings → Credentials** and select **Add credential**.
2. Choose the level: the organization, a space, or your personal space.
3. Type a **Name** in `UPPER_SNAKE_CASE`, such as `STRIPE_API_KEY`.
4. Type the **Value**.
5. Select **Store**. The credential shows in the list with its level.

</Steps>

You can also ask Ren in a chat, as in the example above. Ren asks for the value, or it shows you where to type it.

## Connect an account

Apps and custom MCPs connect through the sign-in page of the provider.

<Steps>

1. Ask Ren to use the app in a chat. Or open the app in **Marketplace → Apps** and add it to a project.
2. Select **Connect** on the card.
3. Sign in to the account that Ren must use.
4. Go back to Ren. The card shows **Connected**.

</Steps>

Ren saves the account in the space of the project. In your personal space, Ren saves it in your personal credentials.

If you connected the account in another of your spaces, the card shows **Reuse** and **Add new**. **Reuse** copies the account into this space.

## What Ren can see

- After you save a credential, nobody can read its value in the app.
- The app shows only the last four characters of a secret, or **Connected** for an account.
- Ren puts each secret into the environment of the machine for the space. The tools and commands that Ren runs can read it.
- Ren does not mask values in command output. If a command prints a secret, the value shows in the chat.

Give Ren a key that has only the access the work needs. Do not give Ren a production root key.

## Change or delete a credential

Open **Settings → Credentials**, find the credential, and open its menu.

| Action           | What it does                                    |
| ---------------- | ----------------------------------------------- |
| **Rename**       | Changes the display name                        |
| **Update value** | Replaces the value of a secret                  |
| **Reconnect**    | Signs in to the account again                   |
| **Transfer**     | Copies or moves the credential to another level |
| **Delete**       | Removes the credential permanently              |

## Good to know

- Each level holds at most 100 credentials.
- Each level holds one credential for each app, custom MCP, or secret name. A new credential for the same app replaces the old one.
- After you delete a credential, chats that use it fail at the step that needs it. Add a new credential to fix them.
- When you change a credential, Ren sends the change to each space that uses it.
- In the API and the CLI, each level has one vault, and each vault holds credentials. Run `ren vaults list` to see the vault for each level. See the [CLI](/docs/surfaces/cli/).
