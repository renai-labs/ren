A custom MCP connects Ren to a server that no [app](/docs/concepts/apps/) covers yet. MCP is a protocol that gives agents access to tools. For example, an internal documentation server can give search tools to every chat of a space.

You add a custom MCP by creating an app for it. The app can hold more than one MCP server, and [skills](/docs/concepts/skills/) that explain how to use their tools.

## Remote and local servers

| Kind       | What you paste                                     | Example                                      |
| ---------- | -------------------------------------------------- | -------------------------------------------- |
| **Remote** | The address of a server that Ren reaches over HTTP | `https://mcp.acme.dev/mcp`                   |
| **Local**  | A command that runs on the machine of the space    | `npx -y @modelcontextprotocol/server-github` |

Ren reads a remote server as soon as you paste its address. It finds how the server signs in, its name, description, and icon, and the tools that it lists without a sign-in. A local server starts only in a chat, so Ren does not read it first.

## Add an MCP server

<SurfaceTabs>
<Fragment slot="app">

<Steps>

1. Open **Apps** and select **Create app**.
2. Paste the server's address or command. For an address, wait for **Checking…** to end. Ren shows the server's name and the number of tools that it found.
3. Check **Auth**. Ren picks it from the server; you can change it.
4. For a local server, add its **Env** values and the names of its **Secrets**.
5. To add a second server, select **Add MCP server**.
6. Pick the space under **Add to**, then select **Create app** or **Create and sign in**.

</Steps>

Select **More** on a server to change its scopes, client ID, name, or description.

## Authentication

For a remote server, choose how Ren signs in:

| Auth         | What you give                                                         |
| ------------ | --------------------------------------------------------------------- |
| No Auth      | Nothing. Use this for public servers.                                 |
| OAuth 2.0    | A sign-in on the provider's page. **Create and sign in** opens it.    |
| Bearer Token | A token that Ren sends as `Authorization: Bearer …` (coming soon)     |
| API Key      | A key that Ren sends in the header that you name, such as `X-API-Key` |
| Basic Auth   | A user name and password (not supported for now)                      |

A key or token that you type in the dialog goes into the app's first account in its space. It never becomes part of the app, so anyone who reads or edits the app does not see it.

A local server's **Env** values are part of the app, and everyone who can see the app can read them. Put a key in **Secrets** instead: each account asks for its value when you connect it.

## Tools

The app's page lists the tools of each remote server. Some servers list their tools only after a sign-in; the page then shows **Tools show after you sign in.** A local server shows **Tools show after the first chat.**

## Connect its credentials

If the server needs a credential that you did not type when you created the app, connect it from the app's page or from the card that Ren shows in a chat. See [Apps](/docs/concepts/apps/#connect-an-account) and [Credentials](/docs/concepts/credentials/).

## Good to know

- Only members of the space that owns the app can edit, move, or archive it.
- To see or paste the whole app as YAML or JSON, select **Spec** in the dialog. See [Spec mode](/docs/concepts/apps/#spec-mode).
