A skill is a reusable set of instructions for a type of task. Its folder contains `SKILL.md` and optional supporting files, such as templates or scripts. Ren reads the description in every chat, but loads the full instructions only when the request needs them.

This example `SKILL.md` is for release notes:

```md
---
name: release-notes
description: Write release notes from merged pull requests. Use when asked for release notes or a changelog.
---

Group changes under Features, Fixes, and Internal.
Link each item to its pull request.
Skip dependency bumps unless they fix a security issue.
```

## Skill or instructions

| Use                                              | For                                                                                     | When Ren reads it       |
| ------------------------------------------------ | --------------------------------------------------------------------------------------- | ----------------------- |
| Project [instructions](/docs/concepts/projects/) | Rules for every chat in a project, such as tone or which repository to work in          | On every turn           |
| A skill                                          | A procedure that only some requests need, or a procedure that you want in many projects | When a request needs it |
| The chat prompt                                  | A one-off request                                                                       | In that chat            |

If you paste the same steps again and again, make them a skill.

## Write a skill

`SKILL.md` starts with frontmatter between two `---` lines. Ren checks it with the [Agent Skills](https://agentskills.io) rules:

| Field                                  | Rule                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `name`                                 | Required. Up to 64 characters: lowercase letters, digits, and single hyphens. It must equal the folder name. |
| `description`                          | Required. Up to 1,024 characters that say when to use the skill                                              |
| `compatibility`                        | Optional. Up to 500 characters                                                                               |
| `license`, `allowed-tools`, `metadata` | Optional                                                                                                     |

No other fields are allowed. Every other file in the folder must be text in UTF-8, such as Markdown, scripts, or templates.

If the skill needs a key, list its env name under `metadata.requiredCredentials`. Each account of the app then asks for its value:

```md
---
name: release-notes
description: Write release notes from merged pull requests.
metadata:
  requiredCredentials:
    - kind: env
      name: GITHUB_TOKEN
---
```

## Add skills to an app

A skill reaches a space through an [app](/docs/concepts/apps/). An app can hold only skills, or skills with the MCP servers whose tools they explain.

<Steps>

1. Open **Apps** and select **Create app**. To add skills to an app you made, open it and select **Edit**.
2. Under **Skills**, drop one or more skill folders on the dialog, or select **Choose folder**. A folder that holds several skill folders adds each of them.
3. To use a skill that lives on GitHub, select **From GitHub** and paste the link to its folder, such as `https://github.com/acme/skills/tree/main/release-notes`.
4. With no MCP server, the app takes the name and description of the first skill. Change them if you like.
5. Pick the space under **Add to**, and select **Create app**.

If a folder breaks a rule, Ren adds nothing from that drop and lists every reason, for example:

```text
✕ Couldn’t add “release”
  • Skill name 'Release_Notes' must be lowercase
  • Directory name 'release' must match skill name 'Release_Notes'
  • assets/logo.png is not a text file
```

Fix the folder and drop it again. A dropped skill with the name of a skill already in the app replaces it.

## Sources

| Source   | How it works                                                                                                          | Use it for                 |
| -------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| A folder | You drop or choose a folder. Ren stores a copy of its files in the app.                                               | Skills you write yourself  |
| GitHub   | You paste the link to a folder. Ren fetches the files from the repository, at the branch, tag, or commit in the link. | Skills you maintain in git |

A skill from a branch follows that branch: new commits change the skill without an edit of the app. Link to a commit to fix its content.

## Edit or remove a skill

Open the app that holds the skill and select **Edit**. To change a skill, drop its folder again. To remove it, select its trash icon. Then select **Save**. Spaces that use the app get the change in their next chat.

To take a skill out of every space, remove it from its app, or archive the app.

## Troubleshooting

### Two skills have the same name or similar instructions

If two apps in a space have skills with the same `name`, Ren loads only the skill of the app that your organization added first. Skills with different names but similar instructions both load. Ren then picks one by its description. Fix: make each description say when to use that skill.

## Good to know

- Only members of the space that owns an app can change its skills.
- To see the skills of an app as YAML, with their files, select **Spec** in the dialog.
