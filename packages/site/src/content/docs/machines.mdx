A machine is the computer where Ren works for a [space](/docs/spaces/). Each space uses two parts:

| Part      | What it does                                              | Example                               |
| --------- | --------------------------------------------------------- | ------------------------------------- |
| **Brain** | Runs the agent: reads your message, decides, calls tools  | Ren thinking about a bug              |
| **Hand**  | Runs the file and shell tools: edits files, runs commands | `bun test` running in your repository |

Most spaces use **Ren's standard machine** for both. Create your own machine when the work needs extra packages, more memory, or limited internet access. Choose which machine each space uses on its [Compute](/docs/compute/) page.

## Create a machine

Only admins can create machines.

1. Open **Settings → Machines** and select **Create machine**.
2. Type a name, such as `Media tools`, and pick the provider.
3. Set what the work needs:

| Setting                           | What it does                                                                 |
| --------------------------------- | ---------------------------------------------------------------------------- |
| Size                              | CPU and memory                                                               |
| Packages and build commands       | Tools to install, such as `ffmpeg`, and commands that run after them         |
| **Chats per machine**             | How many chats share one copy. More chats start another copy.                |
| **Limit hosts**                   | Off: the machine reaches any host. On: only **Allowed hosts**, one per line. |
| **Allow package managers**        | Lets a limited machine reach npm, PyPI and similar registries                |
| **Allow the space's MCP servers** | Lets a limited machine reach the MCP servers of the space's apps             |

4. Select **Create machine**. Ren builds it.

Hosts of the space's [secrets](/docs/credentials/) are always allowed.

## Build status

| Status               | Meaning                                                                  |
| -------------------- | ------------------------------------------------------------------------ |
| **Waiting to build** | The build is in the queue.                                               |
| **Building**         | Ren installs the packages and runs the build commands.                   |
| **Ready**            | Spaces can use it.                                                       |
| **Build failed**     | Open **Details** to read the log, fix the setting, then **Retry build**. |

## Change or archive a machine

- **Edit** in `⋯` changes the settings and builds the machine again. Each space picks up the change when its brain or hand next starts.
- **Shut down spaces** stops every space that uses the machine now, so they start again with the new build.
- **Archive machine** removes it. Its running copies and their files are deleted.
