Add instructions to give Ren lasting guidance on how your team works. Use them for the repository to work in, how to name pull requests, the tone of customer replies, or who approves a deploy.

```md title="Engineering space instructions"
- Work in the northwind/storefront repository unless the request names another.
- Write a test first for every bug fix.
- Never deploy to production. Ask Maya or Dev to deploy.
```

Ren reads them at the start of every chat, so you don't repeat them in each request.

## Scope

Write each rule at the level where it applies:

| Level        | Where                                 | Applies to                     |
| ------------ | ------------------------------------- | ------------------------------ |
| Organization | **Settings → General → Instructions** | Every chat in the organization |
| Space        | The space's **Instructions** page     | Every chat in that space       |
| Agent        | The agent's page, in **Instructions** | Chats where that agent works   |

Keep company-wide rules, such as the brand name or the fiscal year, in the organization's instructions. Put a team's way of working in its space, and a role's job in its agent.

## Order

Ren combines the levels in this order:

1. The organization's instructions
2. The space's instructions
3. The agent's instructions

Ren uses all of them together. It doesn't pick one when two disagree, so write a narrower rule as a clear exception, such as "In this space, staging deploys need no approval."

## Updates

To edit instructions, hover over them and select **Edit**. Press `⌘Enter` to save. Each chat uses the new text from its next message.

## Instructions, skills or the prompt

| Use                           | For                                                    | Ren reads it            |
| ----------------------------- | ------------------------------------------------------ | ----------------------- |
| Instructions                  | Rules for every chat, such as tone or which repository | On every turn           |
| A [skill](/docs/apps/#skills) | A procedure that only some requests need               | When a request needs it |
| The chat prompt               | A one-off request                                      | In that chat            |

Instructions take space in every turn, so keep them short. Move a long procedure, such as how to write release notes, into a skill.

Ren keeps what it learns by itself, such as facts about your customers, in [Memory](/docs/memory/).
