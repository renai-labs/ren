# @ren/mobile

The iOS and Android app: Expo SDK 58, React Native and Expo Router.

## Structure

- `src/app/`: Expo Router file routes. A route file default-exports its screen, the one place Ren allows a default export. `sign-in.tsx` is the only route outside the `(app)` group. The group's layout provides the signed-in user's chat runtime (`ChatReact.runtime`) and a drawer whose content is `#components/sidebar`. Its screens are `index` (a new chat, the home screen), `chats` (search and the full list) and `chat/[id]`. Every screen but the new chat shows `#components/new-chat-button` at the bottom right.
- `index.ts`: the entry. It installs `globalThis.crypto` from `expo-crypto` (`#lib/crypto`) before Expo Router loads, because Hermes has no `crypto.getRandomValues` and `@ren/schema` makes its ID generator at import.
- `src/components/<name>.tsx`: components, imported as `#components/<name>`.
- `src/lib/<name>.ts`: host code (fetch, storage, lifecycle), imported as `#lib/<name>`.
- `src/global.css`: the Uniwind entry, with the fonts: the system font on iOS (SF Pro, as on the web) and Inter on Android, where SF Pro's licence does not reach, and IBM Plex Mono for code. `app.json` registers the font files through `expo-font`; `Text`, inputs and `Markdown` use `font-sans` and `font-mono`. `src/theme.gen.css` holds `@ren/ui`'s theme, generated by `script/theme.ts`. Run `bun run generate` after a theme change in `@ren/ui`, and never edit the file by hand.
- `src/uniwind-types.d.ts`: written by Uniwind's Metro plugin on every bundle. Commit it when it changes.

## Rules

- Depend on `client`, `chat`, `schema` and `util` only; lint enforces it. When a screen needs logic that sits in `@ren/app` and is not tied to the DOM, move it to the package that owns it (usually `@ren/chat`) and use it from both apps. Never copy it.
- State follows `packages/app/AGENTS.md`: server data in TanStack Query, live chat in `@ren/chat` atoms, everything else in the component that owns it.
- Style with Uniwind classes on the theme's tokens (`bg-background`, `text-muted-foreground`), never a raw colour. Uniwind's platform variants (`ios:`, `android:`) are fine.
- Components come from React Native Reusables' Uniwind registry. Copy the component and adapt it to Ren's rules: `cn` from the `cn` package, `use(Context)` instead of `useContext`, named React imports, and a React Native import that collides with the component's name aliased as `<Name>Primitive`. The Reusables CLI does not fit Ren's layout, so do not use it.
- Auth is Better Auth's Expo client in `#lib/auth`. It keeps the session cookie in `expo-secure-store`. The session is a query (`Auth.sessionOptions`), and `src/app/_layout.tsx` guards the routes on it with `Stack.Protected`. After a sign-in or sign-out, `queryClient.resetQueries()` refetches it and clears every other query, and sign-out also calls `ChatReact.forget()`.
- Calls to Ren go through `Api.client` and `Api.query` (`#lib/api`), and those and the chat runtime use `Auth.sessionFetch`. It uses `expo/fetch`, which streams response bodies, and adds the session cookie only for Ren's server.
- Import a Tabler icon from its own entry (`@tabler/icons-react-native/IconLogout`), not the package root, which loads every icon into the development bundle. `src/tabler-icons.d.ts` types those entries.
- Hermes has no `Intl.RelativeTimeFormat`, `Intl.ListFormat` or `Intl.PluralRules`. Shared code the app reaches must not use them; `ToolDisplay.group` uses `Intl.ListFormat`, so call it only after replacing that.
- Workspace packages import their own files with a `.js` extension. `metro.config.ts` strips it for relative imports outside `node_modules`, so Metro finds the `.ts` file.

## Running

- `bun run start` starts Metro for a development build. Expo Go cannot load this app.
- `EXPO_PUBLIC_REN_URL` is the server URL and `EXPO_PUBLIC_REN_APP_URL` the web app's, which the sign-in screen opens to create an account or reset a password (`.env.example`). Both default to production. A phone reaches the machine's LAN address, not `localhost`. The server must trust the app's `ren://` origin, which `server/src/better-auth.ts` does. The chat stream goes to the URL that `chat.access` returns, so a phone needs a server whose brains it can reach.
- EAS builds are limited on the current plan. Start one only when the native side changes (a native dependency, a config plugin, native config in `app.json`, an Expo SDK upgrade), and batch native changes into one build. JavaScript changes reach a development build through Metro and need no build.
- Android development builds are built on the Mac: with `ANDROID_HOME=~/Library/Android/sdk`, run `bunx expo prebuild --platform android`, then `./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a` in `android/`. Install the APK with `adb install` over USB, or upload it with `bunx eas-cli upload --platform android --build-path <apk>`, which gives an install link and uses no EAS build. When the phone cannot reach the Mac on the local network, run Metro with `bun run start -- --tunnel` (needs `npm install -g @expo/ngrok`). It needs the Android SDK command-line tools (`brew install --cask android-commandlinetools`). iOS development builds come from EAS: `bunx eas-cli build --profile development --platform ios`, after registering the iPhone with `bunx eas-cli device:create`.
- Preview and production builds turn on Expo's tree shaking (`eas.json`), which cuts the bundle from about 10 MB to about 4 MB, most of it `effect`. Check a preview build on a device after adding a library with side effects at import.
- Typed routes live in `.expo/types`, which `bun run start` rewrites. A stale copy after a route change fails the typecheck until Metro runs again, or delete it.
- Check a change with `bun run typecheck` and `bun run lint`, and `bunx expo export --platform ios --output-dir <tmp>` when it touches Metro, Babel or a native dependency. Native changes need a new development build.

## Testing

- This package has no unit or component tests. Pure logic is tested in the package that owns it.
- Maestro flows in `maestro/` cover starting a chat, reading the streamed reply and continuing it, with the session already on the device. Run them against a signed-in development build on a device or emulator that `adb` sees, with Metro running and `adb reverse tcp:8081 tcp:8081`: `maestro test maestro/chat.yaml -e METRO_URL=http%3A%2F%2Flocalhost%3A8081`. Each run starts a new chat on the server the app uses.
