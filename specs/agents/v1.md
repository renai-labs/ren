## 1. The parts

An agent is a named set of settings. A user puts it on a session when the session starts. Agents have no runtime and no versions.

Ren, org defaults, space defaults and agents have one shape, Settings.

```

    Settings  =  instructions   +   model and variant   +   permissions


    ┌────────────────────┐   ┌────────────────────┐   ┌────────────────────┐   ┌──────────────────────────┐
    │  REN               │   │  ORG DEFAULTS      │   │  SPACE DEFAULTS    │   │  AGENT                   │
    │                    │   │                    │   │                    │   │                          │
    │  Settings          │   │  Settings          │   │  Settings          │   │  Settings                │
    │                    │   │                    │   │                    │   │  + name                  │
    │  one system row    │   │  one for each org  │   │  one for each      │   │  + description           │
    │  operators seed it │   │                    │   │  space             │   │  + isSubagent            │
    │                    │   │                    │   │                    │   │                          │
    │  v1: instructions  │   │                    │   │                    │   │  owned by one space      │
    │  and model only    │   │                    │   │                    │   │  member of 1..n spaces   │
    └────────────────────┘   └────────────────────┘   └────────────────────┘   └──────────────────────────┘

```

- Ren is the agent of every session that has no explicit agent. It replaces v1's meta agent. It is a system Settings row, not an agent record.
- A space owns its MCPs and skills. An agent adds none. It only changes settings.
- Ren stores Ren, defaults and agents apart. A change to an agent never changes the defaults of a space.

## 2. Ownership and membership

There is no global registry of agents. An agent belongs to the spaces it is a member of.

```

    space "Factory"                          space "Eng"
    ───────────────                          ───────────
    members                                  members
      users:   alice, bob                      users:   bob, carol
      agents:  Build    (owned)                agents:  Triage   (owned)
               Review   (owned)                         Review   (member, owned by Factory)
               Triage   (member, owned by Eng)

    [ + new agent ]  → owned by Factory      [ + new agent ]  → owned by Eng

```

- An agent has exactly one owner space. The owner space is always a member.
- An agent can be a member of other spaces too. Ren keeps a membership row only for a space that is not the owner.
- A user sees an agent in each space where both are members.
- Members of other spaces can use the agent and read its settings. Only the owner space can edit it.
- Ownership can move to any space in the org. The old owner stays a member.
- A space that owns agents cannot be archived. Each owned agent must first move to another owner, or be archived.
- An agent name is unique in the org.

```
    └──────────┬──────────┘                    └──────────┬──────────┘
               ▼                                          ▼
    ┌─────────────────────┐                    ┌─────────────────────┐
    │    org defaults     │                    │   space defaults    │
    └──────────┬──────────┘                    └──────────┬──────────┘
               ▼                                          ▼
    ┌─────────────────────┐                    ┌─────────────────────┐
    │   space defaults    │                    │       agent         │
    └──────────┬──────────┘                    └──────────┬──────────┘
               ▼                                          ▼
    ┌─────────────────────┐                    ┌─────────────────────┐
    │  session overrides  │                    │  session overrides  │
    └──────────┬──────────┘                    └──────────┬──────────┘

```

- One primary agent for each session. The user selects it at start, or Ren applies. It cannot change later.
- The space of a session does not change.
- The UI shows the agent and the overrides: `Ren · model: opus/high`, `Build · +1 instruction`.

## 4. How each field combines

```

    FIELD              RULE                                   EXAMPLE
    ─────────────────  ─────────────────────────────────────  ─────────────────────────────────────

    instructions       add each layer below the last one.     org:    "Never print secrets."
                       Nothing removes the text of a          space:  "We use Bun."
                       higher layer.                          agent:  "You review. Never approve."
                                                              ─────────────────────────────────────
                                                              all three go to the model, in order


    model and variant  the latest layer that sets it wins.    org:    sonnet / medium
                       Model and variant are one unit.        space:  opus / high
                                                              agent:  ─
                                                              ─────────────────────────────────────
                                                              result: opus / high


    permissions        deny and ask rules only. The rules     space:  shell "git push*"  deny
                       of all layers add up. The strictest    agent:  webfetch *         ask
                       match wins. No match is allow.         ─────────────────────────────────────
                                                              result: both rules apply

```

### 4.1 Model and variant

```

    no agent:   session overrides   >   space   >   org   >   Ren
    agent:      session overrides   >   agent   >   space   >   org   >   Ren's model

```

- A model or variant that is not in the catalog: Ren refuses the start or the edit, and names the model.
- The model leaves the catalog while a session runs: the next turn fails, and names the model.

### 4.2 Instructions

Fixed keys, in order: `ren` (only without an agent), `org`, `space`, `agent` (only with an agent), `session`. A session edit changes only `session`.

### 4.3 Permissions

The rule shape of OpenCode 2, without `allow`:

```

    { action,      resource,       effect }

      shell        "git push*"     deny
      linear_*     "*"             deny          (an MCP tool is "<server>_<tool>")
      subagent     "review"        deny          (the main agent cannot start the subagent "review")
      webfetch     "*"             ask

    effect  =  ask  |  deny

```

Everything is allowed by default. A rule only blocks (`deny`) or stops for a person (`ask`). Thus the rules have no order, and the layers need no priority.

One tool call:

```

     tool call: shell "git push origin main"
                         │
                         ▼
     all rules  =  org rules  ∪  space rules  ∪  agent rules  ∪  session rules
                         │
                         ▼
     matching rules:  shell "git push*" deny   (agent)
                         │
                         ▼
     a deny matches?   → DENY
     else an ask?      → ASK
     else              → ALLOW

```

- No layer can open what another layer blocks. There is no `allow` rule to open it.
- There are no allowlists. A layer cannot say "only these tools". A new tool or MCP in the space is allowed until a rule blocks it.
- No matching rule: allow.
- Nobody watches the session (for example a schedule): `ask` becomes `deny`, and the model gets the reason.
- The shape is harness-neutral. Each adapter maps action names (for example `shell` to `Bash`).
- Ren's row has a permissions field. It is empty in v1.

## 5. Subagents

An agent with `isSubagent` is a subagent. Users cannot select it at start. The main agent starts it.

```

    space "Factory"
      ├── member agents:   Build (primary)     Review (primary)     Explore (subagent)
      │
      │
    session s1 in "Factory", agent Build
      │
      │   main agent  ──── "start subagent Explore" ────▶  child session
      │                                                     │
      │                                                     │  settings:
      │                                                     │    org + Factory + Explore
      │                                                     │
      │                                                     │  permissions:
      │                                                     │    org, Factory, Explore
      │                                                     │    AND the parent (Build + overrides of s1)
      │                                                     │
      │   ◀──────────────── result ────────────────────────┘

```

- A subagent that is a member of a space is in every session of that space.
- Its settings are org + space + subagent. It does not get the instructions or model of the main agent.
- Its permissions never exceed the parent's. A change to the parent's permissions reaches its subagents.
- No member subagents: no subagent tool.
- Ren removes the OpenCode agents `build`, `plan`, `general` and `explore`. The hidden title and compaction helpers stay.

## 6. Settings are live

A change to a layer reaches every session that uses it, including running sessions.

```

     a person changes:                                     Ren
       org defaults                                         │
       space defaults            ─────────────────────▶     │  calculates the settings again
       an agent                                             │
       a membership                                         │
       session overrides                                    │
                                                            │
                         ┌──────────────────────────────────┴──────────────────────────┐
                         │                                                             │
                         ▼                                                             ▼
                  PUSH (fast)                                                 PULL (sure)
                  Ren sends the new settings                                  the cell asks Ren for the settings
                  to each cell that is open                                   when it opens and before each turn
                         │                                                             │
                         └──────────────────────────────┬──────────────────────────────┘
                                                        ▼
                                          the cell applies the settings
                                          at the next step: the next model
                                          call or the next tool call,
                                          also in the middle of a turn

```

- Push is the fast path. Pull guarantees that no change is lost.
- An agent leaves the space of a session, or is archived: the session continues as Ren, with its overrides.

## 7. Attribution

Each turn is attributed. The rule:

```

    explicit agent in effect at that turn?
        │
        ├── yes  →  the agent, with its overrides       "Build · model: opus/high · +2 rules"
        │
        └── no   →  Ren, with its overrides             "Ren · +1 instruction"

    subagent turn  →  the subagent                      "Explore (via Build)"
    cost           →  the member who sent the message, and the agent or Ren

```

- Settings are live, so each turn records what it ran with: the agent or Ren, and the overrides with their values.
- After an agent leaves the session, later turns are Ren. Earlier turns keep the agent.
- How Ren stores the attribution is not in v1. The [roadmap](roadmap.md) has it.

## 8. Who can do what

```

    ACTION                                    WHO
    ────────────────────────────────────────  ──────────────────────────────────────────────────
    edit Ren                                  operators (seeded row, no app UI)
    edit org defaults                         org admins
    edit space defaults                       members of the space
    create an agent                           members of the space that will own it
    edit or archive an agent                  members of the owner space, org admins
    see an agent and its settings             members of a space where it is a member, org admins
    add an agent to a space                   members of both spaces, org admins
    remove an agent from a non-owner space    members of that space or of the owner, org admins
    move ownership                            members of both spaces, org admins
    select an agent for a new session         members of the space (member agents only)
    edit a running session                    members of the space of the session

```

Sessions are multiplayer. Every member of the space can take part and edit.

| R3  | What happens to the session overrides on "continue"?       | Ren removes them. The session uses the current settings of the agent.                                        | EXPLICIT |
| R4  | The session is busy when "continue" comes.                 | The message waits in the queue. The new settings apply at the next step.                                     | EXPLICIT |
