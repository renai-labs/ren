# Chat inventory: Ren-specific cases (ren-v1)

Source repos: `../ren-v1` and `../ren-v1-oc-v2`. Many v1 cases are tied to the old sandbox/pod model; the Status column marks each `todo` (port), `n/a` (obsolete in the cell architecture, e.g. pod provisioning, sandbox Basic auth, job polling) or `rethink` (the need remains but the mechanism changes). Choose per row using your judgment and the fact that Ren now runs one Durable Object "cell" per session, reached with a short-lived client token from Ren (`BrainHost.access`).

## transport-v2 status

**Reusable:**

- **fold/**: pure reducers covering step, text, reasoning, tool, retry, inbox, markers and compaction.
- **apply.ts**: session-info patches, execution status, revert commit, inbox and permissions; re-reads on missing records.
- **store.ts**: tracks cold/live origin per message, plus an id index and evict.
- **stream/**: `server.connected` handshake, 2s connect timeout, flat 1s backoff, 16ms frames, delta coalescing.
- **sync.ts** and **reads.ts**: single-flight reads; messages read from the newest 200.
- **send.ts**: prompt with delivery and metadata, cancel inbox item, reply to permission.
- Also reusable: eviction, teardown, selectors, rows, virtualized timeline, tab model.

**Unfinished (final_v2_spec.md §F):**

- F1: the store has no `merge` action.
- F2: pod-store and composer delivery need a live v2 pod.
- F3: richer rendering.
- F4: nothing mounts transport-v2 or v2 yet, and the existing presence component (`PodPresence`) couples provisioning with the v1 stream.
- F5: optimistic echo is undecided.
- F6: no `data-testid` selectors.

**Also missing compared with v1:**

- questions
- attribution
- uploads
- starting an edit or an abort
- titles and list status
- sandbox status (team phase)
- channel parsing
- cold history
- the `waiting` status

v2 views use raw Tailwind rather than `@ren/ui`, so they don't match v1's look.
