# Hot reload: playbook

This folder is the single source for hot reload. An agent that continues this work reads this file first. Update this file in the same change that makes or changes a decision.

Hot reload sends a change in Ren (a setting, an env var, an app, a model, a chat state) to a brain that runs. The brain does not restart.

This folder replaces the older proposal `specs/hot-reload.md` (a poke through OpenCode's well-known config). Git history keeps it.

## 4. Words

| Word     | Meaning                                                                                                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pull     | The brain asks Ren for the full current state (`POST /host/pull`).                                                                                                                          |
| Push     | Ren tells a brain to pull now (`POST /ren/pull`). It carries no data.                                                                                                                       |
| Step     | One model request and the tool calls that it returns. OpenCode reads the tools, the agent and the model at the start of each step (`opencode/core/src/session/context.ts:121-164`, 2.0.27). |
| Drain    | One call of OpenCode's `SessionRunner.drain`. It runs steps until the inbox is empty, so it can include more than one user message.                                                         |
| Turn     | One user message until the agent stops. No code object has this name.                                                                                                                       |
| Location | OpenCode's runtime for one folder (directory and workspace). The sessions in the folder, subagents included, share it.                                                                      |

## 5. Decisions

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HR1  | The brain applies each pulled change to the harness at once. It does not wait until the Location is idle. The harness applies it at its own safe point: OpenCode at the next step, MCP at once. A change or a removal of an MCP server ends a call that runs on that server.                                                                                                                                                | User decision. OpenCode has no turn rule: a reload marks the state changed, and the next read rebuilds it (`opencode/core/src/state.ts:167-194`). The wait for idle (`cell/src/harness/opencode/execution.ts`, `65c8acf75`) kept a server that a person connected during a drain out of that drain. A call that ends on a revoked server is correct: the egress refuses the next request on it (`../credentials/profiles.md:410`). |
| HR2  | Push gives a change at once. Pull gives eventual consistency. A part uses push only when the user must see its change at once.                                                                                                                                                                                                                                                                                              | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HR3  | Models do not go through the pull. The harness reads them from LiteLLM (HR14, HR24).                                                                                                                                                                                                                                                                                                                                        | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HR4  | App catalog (MCP servers, skills): pull every 30 s.                                                                                                                                                                                                                                                                                                                                                                         | User decision. Eventual consistency is acceptable.                                                                                                                                                                                                                                                                                                                                                                                 |
| HR5  | Settings (agents, instructions, permissions, references): push and pull.                                                                                                                                                                                                                                                                                                                                                    | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HR6  | Credential env vars: push and pull.                                                                                                                                                                                                                                                                                                                                                                                         | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HR7  | Public keys and host token: keep what works (pull, and the `ren-host-token` header on each Ren call).                                                                                                                                                                                                                                                                                                                       | User decision. Ren signs only with a key that the brain reported (E45). A brain behind the egress holds no host token (`cell/src/host-token.ts:39-44`); E2B brains go behind the egress when Ren runs one (`core/src/brain-lifecycle.ts:150`, `core/src/sandbox-provider/e2b.ts:169`).                                                                                                                                             |
| HR8  | A push is a "pull now" signal with no data. The pull is the one data path. A lost push delays a change until the next pull; it never loses it.                                                                                                                                                                                                                                                                              | User decision. ren-v1 INV-33: the pull trusted a timestamp that writes set, so a write that did not set it never reached the VM.                                                                                                                                                                                                                                                                                                   |
| HR9  | The pull has no hashes. Ren sends the full state on each pull. The brain compares the content and applies or writes only what changed. Ren ignores the hash fields that old brains send; `host-api` drops them after the old brains are replaced.                                                                                                                                                                           | User decision. The hashes saved only reply bytes: Ren read every input again on each pull (`core/src/brains.ts:455-520`). The brain already compares content for MCP, models, agents and skills (`cell/src/harness/opencode/mcp.ts:250`, `plugin.ts:164`, `:446`, `skills.ts:219`).                                                                                                                                                |
| HR10 | A push starts from Postgres. Triggers on the source tables (`settings`, `agent`, `agent_membership`, `credential`, `app_profile*`, `space_member`, `agent_session`) send a `NOTIFY` with a scope. Ren's server listens and pushes.                                                                                                                                                                                          | User decision. Postgres delivers a `NOTIFY` only at commit, so a brain never pulls rows from before the write. No write point can forget it (ren-v1 INV-33). Each server instance gets each signal; a repeated push costs one more pull.                                                                                                                                                                                           |
| HR11 | A row with a space pushes to the brains of that space. A row with an org and no space pushes to the brains of the org.                                                                                                                                                                                                                                                                                                      | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HR12 | A push goes to every brain of the scope. Ren calls `BrainHost.notify(brainId)`, with a 2 s timeout and a limit on parallel calls. A failure is ignored. `layerCell` calls the cell; `layerSandbox` calls the URL in the brain row. `notify` never calls `access`, `ensure` or `touch`.                                                                                                                                      | User decision. `layerSandbox.target` calls `access` (`core/src/brain-host.ts:72-73`): for a paused brain it resumes the sandbox (`ensure`, `core/src/brain-lifecycle.ts:554`); for an awake brain it extends the keep-alive (`touch`, `:548-550`). A paused E2B sandbox does not resume on HTTP: Ren creates it without `autoResume` (`core/src/sandbox-provider/e2b.ts:193`). A cell opens on the call.                           |
| HR13 | The brain serves `POST /ren/pull` (server token, no body, `202` at once). A push during a running pull marks one more pull, which starts when the running pull ends. More pushes in that time add nothing.                                                                                                                                                                                                                  | User decision. ren-v1 joined the running refresh (`manifest-driver.ts:51-57`), so a write after its read waited for the next timer. Today's lock queues one pull per push (`cell/src/hot-reload.ts:50`).                                                                                                                                                                                                                           |
| HR14 | The harness reads LiteLLM `GET /model/info` every 30 s, with the brain's model key (behind the egress: the placeholder `ren:MODELS`). It keeps the last list when LiteLLM fails, and stores it in brain storage for a restart. On a `start` or `setModel` with a model it does not know, the brain calls `refreshModels`, then checks again.                                                                                | User decision. `/v1/models` has no limits and no modalities; without them OpenCode compacts too early and refuses images (`ren-v1/packages/inference/src/harness/harness/opencode.ts`, quirks marked `required`). Prior art: `cell/src/brain.ts:54-61`.                                                                                                                                                                            |
| HR15 | One harness-neutral function, `Models.fromLiteLLM`, turns LiteLLM's model list into `Models.Catalog`. Ren's server (picker, model checks) and each harness adapter use it. It drops `routing: openrouter-fallback`. It does not filter by key: LiteLLM does (see Why). `endpointId` = `model_info.provider_key`, `modelId` = `model_info.model_key`, so stored choices still resolve (E59).                                 | User decision. ren-v1 kept the projection in the API (`ren-v1/packages/api/src/model/CLAUDE.md`).                                                                                                                                                                                                                                                                                                                                  |
| HR16 | The pull reply carries LiteLLM's base URL. A move reaches running brains within 30 s.                                                                                                                                                                                                                                                                                                                                       | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HR17 | An open cell pulls every 30 s: `Cell.alarm` starts `hotReload.pull` in its own fiber while the harness is open. A closed cell pulls on its next request. `/ren/pull` uses the same handler wrapper as the other Ren calls, so a push also gives the cell a fresh host token.                                                                                                                                                | User decision. The alarm did reconcile and sync only (`cell/src/cell.ts:129-194`). Every Ren call carries `ren-host-token` (`cell/src/brain.ts:65-71`); a cell with an expired token skips its pull (`cell/src/hot-reload.ts:61`).                                                                                                                                                                                                 |
| HR18 | A removed env var leaves the brain at once, on the pull that removes it. `CredentialEnv` drops `wanted`, `applied` and `turnEnded`. This replaces C47's turn-end rule (`../credentials/README.md:497`).                                                                                                                                                                                                                     | User decision. A process reads its env once at start, so a running script keeps its copy. Only the Bun brain called `turnEnded`, on any chat's turn end (`cell/src/bun.ts:127-130`); a cell never called it, so a removed var stayed until a restart.                                                                                                                                                                              |
| HR19 | Ren waits for MCP servers only at boot: the first turn waits until the catalog's servers connect or time out (`cell/src/harness/opencode/mcp.ts:223`). After a reload Ren does not wait.                                                                                                                                                                                                                                    | User decision. `mcp.reload()` returns only after OpenCode connects and lists the tools, or fails (`opencode/core/src/mcp/index.ts:427-467`); the tools join the list about 100 ms later (`tool/mcp.ts:140`). At boot OpenCode connects in the background and a step reads only connected servers (`mcp/index.ts:663`).                                                                                                             |
| HR20 | The profile of an MCP server goes into the description of that server's tool namespace (`ToolEditor.namespace({ name, description })`). The "unavailable" and "no environment" notes are dropped. Only the env key note stays in the system prompt.                                                                                                                                                                         | User decision. The `context` hook writes the system prompt (`cell/src/harness/opencode/mcp.ts:227-243`); a note change costs a full prompt cache write. OpenCode sends tool catalog changes as short messages, so the cache is kept (`opencode/core/src/session/instruction-state.ts:38-63`). OpenCode already leaves out the tools of a missing server.                                                                           |
| HR21 | Settings (chat agent, chat model, agent instructions, permissions, references) apply at the next step, as OpenCode does. No Ren code waits. An edited agent prompt costs one prompt cache write. A subagent whose agent is removed fails at its next step, and its parent gets a tool error.                                                                                                                                | User decision. `switchAgent` and `switchModel` only record an event, with no busy check (`opencode/core/src/session/session.ts:89-108`). Ren's permission hook reads the current rules on each check (`cell/src/harness/opencode/plugin.ts:379-411`).                                                                                                                                                                              |
| HR22 | Ren deleting a busy chat interrupts its turn, then drops it, as for an archived chat.                                                                                                                                                                                                                                                                                                                                       | User decision. The brain skipped a busy deleted chat until its turn ended (`cell/src/hot-reload.ts:108-114`), so the turn kept spending tokens.                                                                                                                                                                                                                                                                                    |
| HR23 | Archive, delete and a chat's agent change push. The trigger on `agent_session` fires on `DELETE`, and on `UPDATE OF archived_at, agent_id` only when one of them changes (`WHEN OLD.x IS DISTINCT FROM NEW.x`).                                                                                                                                                                                                             | User decision. Sync updates `agent_session` on each upload (`core/src/session-sync.ts:155`, `:202`, `:224`); a trigger on every update would push on every sync. Postgres fires row triggers on cascade deletes too. ren-v1 OI-20: an archived chat's turn kept running.                                                                                                                                                           |
| HR24 | The harness reads LiteLLM itself. OpenCode gets a Ren plugin built on OpenCode's own provider discovery: it reads `/model/info` (HR14), maps it with `Models.fromLiteLLM` (HR15), and reloads OpenCode's providers when the list changed. Ren's brain code does not poll models. Each later harness reads LiteLLM in its own adapter with the same function. `Harness.Instance.refreshModels` asks the harness to read now. | User decision. Prior art: `opencode/core/src/plugin/provider/local.ts:93-125` (2.0.27).                                                                                                                                                                                                                                                                                                                                            |
| HR25 | Ren's own settings row and global agents (no org, no space) push to every brain in Ren.                                                                                                                                                                                                                                                                                                                                     | User decision. ## 6. Open

1. **Missing tests (found in review):** the brain side of key rotation (`specs/runtime/e2b-brain/c-tokens.md` test 8) and the 1 h host token renewal point (`cell/src/host-token.ts:11`; the test at `cell/test/host-access.test.ts:172` uses 120 s and says "five minutes").
2. **A chat's own model pick when its model leaves LiteLLM**: covered by test 33; confirm the fallback message in the app.
3. **U1 and U2 are deferred (user decision).** U2 needs a way to edit an agent in the app; the app has no agent UI and Ren's API has no agent endpoint. U1 needs a Linear sign-in, which a local run cannot do. C1 covers the behaviour of U2 on the real chain.
4. **A model key per brain:** Ren mints one `MODELS` key per brain (`../credentials/README.md` C29). Then the grant holds one LiteLLM key, and `ModelRefresh.anyEndpoint` and the first-key fallback go (HR33, HR37).
5. **The 3 `openai` models without `mode` (HR31)** are not run on LiteLLM: the local LiteLLM has no OpenRouter key. Run one turn on each once it has one.
6. **Tests not written yet (user decision: follow-up):** package tests 7, 15, 16, 28, 30, 33, 36 (brain side), 38–40, 44, 45 of [`references/tests.md`](references/tests.md), and chaos cases C2, C3, C8, C9 of [`spec.md` §9.1](spec.md#91-chaos-cases).
7. **Runs not repeated on the final commit (user decision):** the full `bun run chaos` (its 18 failures from `main` were each fixed and run alone), the seeded sequences, Playwright, `REN_SLOW=1` and the live lane (each live file passed alone on the final code).
8. **From the final review (follow-up):** F5, the app loads a chat's model, agent and skill lists once per open, so a change shows only after a reload (`chat/src/atoms.ts:183`); F7, the `BrainPush` reconnect test and the real-stack chaos file fail under load or after an earlier test hangs; F8, a Ren-wide write opens every cell once per server instance (HR10, HR12, HR25). Coupling: chat history is OpenCode rows end to end; the brain reads LiteLLM inside the OpenCode adapter; the LiteLLM schema lives in `@ren/schema`; the lifecycle assumes the provider pauses at a deadline (E2B).
