## 1. Goal

People connect, see, share and remove credentials with the same UX as ren-v1, in the composer, in the chat and on the settings pages. Ren keeps each credential with one owner and applies the owner rules of README section 6.4.

Done when:

- In a new chat, the composer shows "2 not connected" for a space that uses the Stripe and Linear apps. The person connects Linear with OAuth and pastes the Stripe key from the composer. The pill goes away.
- In a chat, the agent calls Gmail. The egress refuses with `credential_missing`. The agent tells the person which key to connect (a connect tool and card come with Ren MCP, later). The person connects it. The agent goes on.
- A space serves two customers with two Meta Ads connections. Code mode calls each one with its own credential.
- A member leaves the org. Their personal credentials and their account credentials in every space are gone. The Stripe key that they pasted for a space stays.

Not in this spec: app use, MCP and skill tables and editors (REN-1429); asks and grants (REN-1449); the GitHub App installation flow (its owner is A31).

## 2. Words

| Word               | Meaning                                                                                                          |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| Owner              | The one party that a credential belongs to: `workload`, `person`, `space` or `org`.                              |
| Account credential | A credential from a sign-in to a person's own account (Gmail, GitHub user). `account_user_id` names that person. |
| Pasted key         | A credential whose value a person types in. It has no `account_user_id`.                                         |
| Requirement        | A credential that an app, a skill or an MCP declares in `requiredCredentials`.                                   |
| Gap                | A requirement that does not resolve for the workload of a chat.                                                  |
| Connection         | One credential of an MCP in a space. One MCP can have several.                                                   |
| Destination        | The owner that a new credential gets in a connect flow.                                                          |

## 4. Owners and permissions

Roles: `owner` and `admin` are admins; `member` is a member (`schema/src/auth.ts:22`).

| Action                            | org credential   | space credential                                                      | person credential  | workload credential |
| --------------------------------- | ---------------- | --------------------------------------------------------------------- | ------------------ | ------------------- |
| See metadata                      | every org member | space members, admins                                                 | the person, admins | nobody (Ren only)   |
| Create, rotate, reconnect, rename | every org member | space members, admins                                                 | the person         | Ren                 |
| Delete                            | every org member | space members, admins                                                 | the person, admins | Ren                 |
| Move, copy                        | every org member | space members, admins; an account credential: the account holder only | the person         | —                   |
| Choose `delivered` (README §9)    | admins           | space members, admins                                                 | the person         | —                   |

Rules:

1. No API returns a secret. A read returns the metadata and a key preview (A5).
2. A move or a copy needs the right to create at the target owner.
3. Only the account holder moves an account credential, and only to a space that they are a member of. The account holder can always delete it, or move it back to `person` (A6).
4. Copy is for pasted keys only. OAuth, `route` and `client_credentials` credentials move only (A7).
5. An admin never moves, copies or uses a person credential (A4).
6. Ren checks the owner rules when a connect starts, before the consent screen (README §6.4 rule 3).

`core/src/credential/policy.ts` states the table as `Policy.Document` statements, like `core/src/space/policy.ts`. Relationships: `credential.org`, `credential.space`, `credential.spaceMember`, `credential.person`, `credential.self`. Example: create allows every role on `credential.org`, `credential.spaceMember` and `credential.self`, and admins on `credential.space`. `Credentials.move` checks rule 3 in code, because a policy cannot state "only the account holder".

| `oauth_app`     | `id` (`oap_…`), `organization_id`, `name`, `provider`, `client_id`, `client_secret` (`Sealed`, context kind `oauth_app`), `scopes`, `discovery`, `authorization_endpoint`, `token_endpoint`, `token_endpoint_auth`, `resource`, `authorize_params`, `pkce`, `configured_by_user_id`, `created_at`, `updated_at`, `archived_at`                                                                                              | Unique `(organization_id, name)` where `provider` is null and not archived. Unique `(organization_id, provider)` where `provider` is not null and not archived.                                                                                                                                                                                         |

Rules:

1. `type` is `key`, `basic`, `oauth`, `fields`, `route` or `client_credentials`. A change of type is delete, then create (ren-v1 bug 12).
2. `value` holds the whole secret, refresh data included. Its `Envelope` context is `{ organizationId, "credential", id }`, so a move changes the owner columns only (A1).
3. `label` never changes after create, because running workloads hold `ren:<LABEL>`. `name` is the display name; a rename changes only `name` (A22).
4. A credential is deleted, never archived (A11). `oauth_app` archives, because MCPs name it (README §6.9 rule 6).
5. A `workload` credential has no generation in its key. It stays when Ren replaces the machine (A16).
6. `scopes` holds the granted scopes. When a declaration asks for more, the credential has status `reconnect` (README §6.9 rule 4).

## 6. Labels and connections

| Source                                          | Label                                                                                                                 |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| A requirement with an env name                  | the name, for example `STRIPE_API_KEY`. Every consumer of that name shares it.                                        |
| An MCP with `secret`, `text` or `select` fields | `MCP_<SLUG>`, type `fields`: one row for all fields                                                                   |
| An `oauth` MCP                                  | `MCP_<SLUG>`, or the optional `credential` of `Mcp.Auth.oauth` (to share one sign-in with a channel, ren-v1 REN-1156) |
| A named connection                              | `MCP_<SLUG>__<CONNECTION>`                                                                                            |
| GitHub user sign-in                             | `GITHUB`                                                                                                              |

1. `<SLUG>` is the MCP slug in upper case with `-` changed to `_`. A slug has no `_` and no double dash (`schema/src/primitive.ts:17`), so two slugs never give one label, and `__` always separates the connection.
2. The connections of an MCP in a space are the credentials that resolve for the space with labels `MCP_<SLUG>` and `MCP_<SLUG>__*`. No other table holds them (A25).
3. The Ren plugin writes one OpenCode MCP entry per connection: `<slug>` or `<slug>-<connection>`, with the header `Authorization: Bearer ren:<LABEL>` (A14). For a `header` or `basic` MCP, the header holds the placeholders of its fields.
4. A new connection gets its OpenCode entry at the next turn (README §10 rule 6).

Example: space `agency` has `MCP_META_ADS__ACME` and `MCP_META_ADS__GLOBEX`. Code mode calls `meta_ads_acme.list_campaigns()` and `meta_ads_globex.list_campaigns()`. Every chat of the space can call both (C7). To keep two customers apart, use two spaces.

## 9. Connect flows

```
 app                          server / core                                                         provider
 POST /credentials/connect
 { owner, target,         ─▶ ① Access and owner rules (section 4); refuse before consent
   reconnect? }               ② client: org app (an oauth_app requirement) → borrowed client → Ren's client
                                 metadata document → dynamic registration                         (A17)
                              ③ oauth_session { state, PKCE verifier, owner, label, resource }, 10 min
 ◀── WriteResult.Redirect { redirectUrl, expiresAt }
 new tab ─────────────────────────────────────────────────────────────────────────────────────────▶ consent
 GET /oauth/callback?state&code ◀─────────────────────────────────────────────────────────────────── redirect
                              ④ consume state once (UPDATE … WHERE consumed_at IS NULL)
                              ⑤ exchange → require a refresh token → Envelope.seal → save in one transaction
                              ⑥ the old credential stays valid until ⑤ is done (README §6.9 rule 5)
 tab closes; the dialog or card reads oauth-session.get → complete → asks for requirements again
```

| Flow                                | The person gives                                                 | Ren stores                                                                                              | Destination                                           |
| ----------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| OAuth MCP                           | consent                                                          | `oauth`, `account_user_id` set                                                                          | `person`; `space` when the chat runs on a space brain |
| Built-in client                     | consent; for a `127.0.0.1` redirect, the pasted callback address | as OAuth MCP                                                                                            | as OAuth MCP                                          |
| Org OAuth app                       | client id and secret, endpoints, scopes                          | `oauth_app`; then as OAuth MCP                                                                          | org (A18)                                             |
| Managed MCP provider (Composio now) | consent in the provider                                          | `route` with `provider` set (the session URL); the provider's headers become `setHeader` ops (A36, C36) | `person`                                              |
| Client credentials                  | client id and secret, token endpoint                             | `client_credentials`; Ren exchanges and refreshes (A20)                                                 | `space` or `org`                                      |
| Pasted key                          | the value; hosts are filled in from the declaration              | `key`, `basic` or `fields`; each completed field saves at once (UX lesson 7)                            | the destination that the dialog shows                 |
| GitHub user                         | consent                                                          | `oauth` `GITHUB`, and the git identity values (README §6.5)                                             | `person`                                              |

Rules:

1. Each refresh rule in [`references/ren-v1.md`](references/ren-v1.md) applies to `OAuth` and has a test (section 16).
2. The return address is Ren's config, never the caller's (README §6.9 rule 3). `GET /oauth-apps/redirect-uri` shows it before a person registers an app.
3. The callback has no login check. `state` is the authentication. When the browser has a session, Ren also checks that it is the initiator (`OAuth.StateInvalid { reason: "other_user" }`).
4. The refresh sweep also deletes `oauth_session` rows older than 1 day.

## 10. Requirements

`CredentialRequirements.forSession(session)`:

1. Read the apps that the session's space uses (REN-1429), and their skills and MCPs.
2. Collect `requiredCredentials` and the labels of section 6. Key each item by what satisfies it: one label is one item (ren-v1 UX lesson 13). An MCP with auth `none` has no item.
3. Resolve each label with the session's workload: lookup order workload, person, space, org; a person credential counts only when the workload serves that person alone (README §6.4 rule 2).
4. Set `status`: `ok`, `missing`, or `reconnect` (section 5 rule 6).
5. Set `destinations`: `person`, `space`, `org` for a session-scope brain; `space`, `org` for a space brain. An account sign-in lists `person` first when it is allowed.

`forNewSession(space, person)` does the same for the workload that a new chat of that person in that space would get (`space.brain_scope`).

The app asks for the list again after each of its own changes and on window focus. It does not poll (A8).

`ren_connect({ label })` is a tool of the Ren plugin in the brain. The egress refusal for `credential_missing` names the label and tells the agent to call it. The tool returns at once. The app draws the card from the tool part. After the connect, the card sends `connected <LABEL>` as a message, and the agent goes on (A9).

## 11. Offboarding and limits

| Event                                  | Hook in v2                                                                          | Ren deletes                                                                              |
| -------------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| A member leaves the org                | `afterRemoveMember` (`server/src/better-auth.ts:167`), next to `archiveMemberships` | The person's credentials in the org; their account credentials in every space of the org |
| A member leaves a space                | space-member `archive` (`core/src/space.ts:56`)                                     | Their account credentials in that space                                                  |
| A space is archived                    | space `archive`                                                                     | All credentials of the space                                                             |
| A user is deleted                      | FK cascade on `user_id` and `account_user_id`                                       | All their rows                                                                           |
| An org OAuth app is archived (`force`) | `OAuthApps.archive`                                                                 | Every credential that the app issued                                                     |
| A brain or a hand is removed           | its delete                                                                          | Its workload credentials                                                                 |
| A space stops using an app             | —                                                                                   | Nothing. The credential can serve other consumers.                                       |
| A refresh fails with a fatal error     | the refresh sweep                                                                   | That credential; the requirement shows `missing` (ren-v1 bug 3)                          |

After each delete, Ren clears the egress answer cache for the affected workloads at once (README §6.4 rule 6).

Limit: 100 credentials per owner (ren-v1 `vault/credential.ts:44`). The create, move and copy transactions lock the owner's row (`space`, `member`, `organization`) before they count.

## 12. Infra bindings

1. `Infra.SpaceBindings.credentials` (`schema/src/infra.ts:194`) stays. A binding is a label alias: app `stripe`, requirement `STRIPE_API_KEY` → `STRIPE_EU`. The workload then gets `STRIPE_API_KEY=ren:STRIPE_EU`.
2. Without a binding, the requirement name is the label.
3. A binding names a space or an org label. It never names a person credential (`specs/infra.md` §8 item 6). `Infra.Spec` validation cannot see owners, so `plan` checks it.
4. Connections are not in `deploy.yaml`. They come from credential labels (section 6 rule 2).

## 14. Lifecycle states

| State                                     | What happens                                                                                                             |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Brain asleep                              | Nothing to do. On wake, the pull carries the current env layer and MCP entries.                                          |
| Brain mid-turn: connect                   | The next request gets the credential (no cache for `credential_missing`). A new MCP connection appears at the next turn. |
| Brain mid-turn: delete, move, offboarding | The cache is cleared at once. The next request is denied, or resolves for the new owner.                                 |
| Brain mid-turn: rename                    | Nothing changes for the workload. The label stays.                                                                       |
| Ren restarts during a sign-in             | `oauth_session` is in Postgres. A callback within 10 minutes still completes.                                            |
| Ren is down at the callback               | The provider redirect fails. The person tries again. The old credential is still valid.                                  |
| Two connects at once for one label        | The second save gets `Credentials.LabelTaken`, unless it is a reconnect of the same credential.                          |

## 17. Decisions

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A1  | No vault object. Each `credential` row holds its owner in owner columns, with a check that exactly one owner is set. A move changes the owner columns only, because the `Envelope` context is the credential id (README §6.8). Ren deletes credentials on space archive and on member removal.                                                                                                                                                                                                                                                         |
| A2  | Every org member may create, rotate and delete org credentials (as ren-v1, `server/routes/vault.ts:233,337`).
