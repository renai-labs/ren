## 1. Goal

No third-party credential reaches a brain or a hand. An egress proxy adds each credential to the request after the request leaves the workload. Code mode stays on.

Done when:

- A chat calls an MCP server, a model, a CLI (`gh`, `curl`) and a skill script that need credentials. The brain and the hand hold only placeholders.
- No token in a brain or a hand needs renewal, except the fallback token (C3) on hosts that cannot identify a workload.
- A change of the encryption backend (local keys to AWS KMS), the proxy, the brain host (sandbox, celld, Cloudflare Durable Object), the sandbox provider (E2B, Daytona, Modal) or the hand type (sandbox, laptop, phone) is a new layer. Callers do not change.

Not in this spec: approvals for writes (REN-1449), metering (REN-1482), Ren as an MCP server (REN-1457, REN-1475).

This spec covers how a credential reaches a request. How people manage credentials is in [`owner-access.md`](owner-access.md) (REN-1432). Build both together; neither is complete without the other (C34). Section 2a lists its scope.

## 2. Words

| Word             | Meaning                                                                                              |
| ---------------- | ---------------------------------------------------------------------------------------------------- |
| Workload         | Code that runs for Ren: a brain or a hand. Key: `{ kind, id, generation }`.                          |
| Egress           | The proxy that all outbound traffic of a workload goes through. It adds credentials.                 |
| Proof            | What the egress shows Ren to say which workload sent a connection.                                   |
| Placeholder      | A stand-in value in the workload, `ren:<LABEL>`. The egress replaces it with the real value.         |
| Delivered secret | A real secret that Ren puts into a brain or a hand, because the egress cannot inject it yet.         |
| Egress principal | A party that may call Ren's egress endpoints: Ren's own egress, or a customer's proxy for one org.   |
| Registered key   | A public key that a party registers with Ren. The party keeps the private key. Ren stores no secret. |

## 3. Rules

1. A credential lives in Ren only. Ren encrypts it with `Envelope` (C18).
2. The host or the provider says which workload sent a connection. The request never says it (C2).
3. The workload holds public keys and placeholders only. The exception is a delivered secret (C9).
4. Every token with a lifetime lives in a part that does not sleep: Ren or the egress. Ren renews. A brain or a hand renews nothing (C3).
5. Every replaceable part is an Effect service. Only a composition root picks a layer.

## 4. System

```
 workload (brain or hand)          host / provider                 egress (iron-proxy, or other)            Ren
 ┌────────────────────────┐ call  ┌──────────────────────┐ proof  ┌────────────────────────────┐ resolve  ┌────────────────────────────────────┐
 │ public keys            │ ────▶ │ adds the proof:       │ ─────▶ │ ① finds placeholders        │ ───────▶ │ CredentialCallers.verify → Workload │
 │ placeholders ren:LABEL │       │ proxy login, address, │        │ ② asks Ren (cache 30 s)     │ ◀─────── │ match → CredentialSource → plan     │
 │ plain env values       │       │ host stamp, token     │        │ ③ injects, forwards         │  inject  │ Envelope.open (local or KMS)        │
 └────────────────────────┘       └──────────────────────┘        └──────────────┬─────────────┘          └────────────────────────────────────┘
          ▲ Ren → brain: server token. Browser → brain: client token.             ▼
          │ The brain checks both with Signer public keys.            Ren (REN_URL), model, MCP, APIs, git
```

E2B brain with its own hand: E2B sends all TCP of the sandbox to the egress with a proxy login that Ren set at create. The sandbox does not see the login. Nothing in the sandbox needs renewal.

Ren is the control plane: it decides who calls and what to inject. The egress is the data plane: it moves bytes. They are separate processes (C22). They can run in the same pod or machine.

## 6. Contracts

### 6.1 Workload

```ts
// @ren/schema/workload
Workload = { kind: "brain" | "hand", id: Brain.ID | Environment.ID, generation: number }
```

A hand gets `generation` on its `environment` row. Ren increments it when it replaces the hand's machine.

### 6.2 Placement and proof

`CredentialCallers.issue(workload)` returns a placement. The host or provider layer uses it at create. `CredentialCallers.verify(principal, proof)` returns the workload, or none.

| Proof kind   | Placement (Ren → host or provider)                                            | Proof (egress → Ren)     | Verify                                                               | Hosts                                 |
| ------------ | ----------------------------------------------------------------------------- | ------------------------ | -------------------------------------------------------------------- | ------------------------------------- |
| `ProxyLogin` | `{ username, password }`, given to the provider. Never put into the workload. | `{ username, password }` | password hash matches; generation is current                         | E2B (BYOP); local dev (`HTTPS_PROXY`) |
| `Address`    | none. The provider layer reports the address after create.                    | `{ address }`            | address maps to the workload; the principal is on that network       | Docker, Kubernetes, own VMs           |
| `HostStamp`  | none                                                                          | `{ workload }`           | the principal is a host gateway that may name workloads of that host | celld, Cloudflare Durable Object      |
| `Token`      | `{ token }`, put into the workload                                            | `{ token }`              | `Signer` signature; `exp`; generation is current                     | any other host or hand (fallback)     |

The `credential_caller` table keeps one row per workload and generation: `{ kind, id, generation, proofKind, username, passwordHash, address, revokedAt }`. Revoke sets `revokedAt` and removes the address mapping before the provider frees the address.

### 6.3 Resolve

One function in core. Two transports call it: the iron-proxy transform (gRPC over mTLS) and `egress-api` (HTTP).

```
Egress.resolve(principal, request) → reply

request {
  proof,
  host: "api.stripe.com", port: 443, method: "POST", path: "/v1/charges",   // the host the egress dials
  placeholders: ["ren:STRIPE_API_KEY"],          // the placeholders the egress found in the request
}

reply
  | { allow: true, workload: "brain:brn_7f2:3", ttl: 30, expiresAt?: 1793000000,   // Unix s; first value's expiry
      inject: Array<
        | { op: "replace",   placeholder: "ren:STRIPE_API_KEY", value: Redacted, in: ["header"] }
        | { op: "setHeader", name: "Authorization", value: Redacted }        // by host, no placeholder
        | { op: "route",     upstream: Redacted }> }                         // the secret is the upstream URL
  | { allow: false, reason: "unknown_workload" | "generation_retired" | "host_not_allowed"
                          | "credential_missing" | "ambiguous" | "principal_scope" }
```

1. The egress keeps a reply in its own process for `ttl` seconds (30). The cache key is the proof, the host and the placeholder set. When Ren does not answer, the egress uses the last `allow` reply for up to 15 min; it never does this for a denial, for an entry that Ren invalidated, for a reply that was in flight during an invalidate, or after the reply's `expiresAt` (C37).
2. A placeholder sent to a host that is not in the credential's `hosts` gets `host_not_allowed`.
3. When two credentials match one host and the request has no placeholder, the reply is `ambiguous`.
4. A principal limited to org `org_9` gets `principal_scope` for a workload of another org.
5. `host` is the host that the egress dials. For a tunnel, the `CONNECT` target, the TLS name (SNI) and the `Host` header must be the same. Otherwise the egress refuses the request.
6. The egress encodes each value for its location: percent-encoding in the query and the path. A value with CR or LF never goes into a header; the reply is `credential_missing` with a log entry.
7. The egress never follows a redirect. A redirect goes back to the workload, which sends a new request. That request is resolved again for its own host.
8. The egress denies a dialled address in a private, loopback, link-local or metadata range, also for an allowed host name.
9. A denial for `credential_missing` names the label, so the app can show a connect card. The egress does not cache it, so a credential that a person connects works on the next request.
10. When an upstream answers 401 to a request with an injected OAuth credential, the egress tells Ren. Ren refreshes that credential once. The workload retries.
11. The egress masks an injected value that comes back in a response with a known length (an error body, for example). It does not buffer streams to mask them.
12. Logs and audit records hold labels, never values. A body capture runs before the swap.
13. When no credential matches, the egress never uses a deployment credential (a Ren key, a cloud role) in its place.

### 6.4 Credential

```ts
// stored in Ren; value sealed by Envelope
Credential = {
  label: "STRIPE_API_KEY",
  owner: { workload } | { person } | { space } | { org },  // workload: credentials that Ren mints, e.g. the model key
  value: Sealed,
  expiresAt?: DateTime,                        // from the upstream; Ren refreshes before it
  hosts: ["api.stripe.com"],
  inject: { op: "replace", in: ["header" | "query" | "path" | "body"] }
        | { op: "setHeader", name: "Authorization", format: "Bearer {value}" | "Basic {basic}" }  // {basic} = base64(username:password), built by the egress
        | { op: "route" },                                                                    // value is the upstream URL. A provider source also gives headers; they become setHeader ops (C36)
  delivery: "egress" | "delivered",           // delivered: real value into the workload; marked in the UI
}
```

Lookup order for a label: workload, then person, then space, then org. The first match wins. A lookup never crosses into another space.

Owner rules:

1. A sign-in to a person's own account (Gmail, GitHub user OAuth) makes a `person` credential. A person can share it with a space; the UI then shows whose account it is (ren-v1 REN-1271: a shared vault held one person's Gmail, and another person's agent read that inbox).
2. A `person` credential resolves only on a workload that serves that person alone: a brain with scope `session`, or a hand with `sessions_per_environment = 1`.
3. Ren checks the owner rules when a sign-in starts, not after the consent screen (ren-v1 `4e5d2e946`).
4. One credential can have several consumers: an MCP server, a channel integration, a skill (ren-v1 REN-1156).
5. Labels are unique per owner and use `Credential.EnvName` (`UPPER_SNAKE_CASE`). A second credential with the same label on the same owner is an error, never a silent replace (ren-v1 INV-48).
6. Deleting a credential, removing a member and uninstalling an app clear Ren's answer cache for the affected workloads at once.

Ren mints these kinds itself. Each mint runs one at a time per workload, never returns an empty value, retries on an upstream 5xx, and keeps the old value valid until its own expiry (ren-v1 INV-24, INV-25, INV-26, OI-11):

| Label                                     | Owner        | Hosts                          | Value                                                                        | Refresh                                                                                                |
| ----------------------------------------- | ------------ | ------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `REN`                                     | workload     | the host of `REN_URL`          | host token, `Signer`, 2 h (`host-api/src/brain-token.ts:52`)                 | Ren signs a new one 20 min before `exp` (C37).                                                         |
| `MODELS`                                  | workload     | model endpoint hosts           | model key from `Models.grant`; a LiteLLM key after piece H                   | Ren, before the upstream expiry                                                                        |
| `GITHUB_INSTALLATION`                     | space or org | `api.github.com`, `github.com` | GitHub App installation token, 1 h                                           | Ren mints it when it is needed; never stored. Two installations for one space is an error, not a pick. |
| any label with a client-credentials grant | space or org | from the declaration           | access token from `grant_type=client_credentials` (Shopify, ren-v1 REN-1198) | Ren exchanges and refreshes it                                                                         |

### 6.5 Env vars

```ts
// declared by a skill, an app or space settings
EnvVar = {
  name: "STRIPE_API_KEY",
  target: ["brain"] | ["hand"] | ["brain", "hand"],
  source:
    | { kind: "value",      value: "https://api.acme.dev" }                    // plain; visible to the agent
    | { kind: "credential", label: "STRIPE_API_KEY", shape?: "sk-ren-{label}" } // the workload gets the placeholder
    | { kind: "delivered",  label: "PG_PASSWORD" },                            // real value; section 9
}
```

Until apps and skills declare env vars, every `key` credential that resolves for the workload becomes `<LABEL>=ren:<LABEL>` (`owner-access.md` A35).

| Target | Arrives                                                                                                 | A change applies           |
| ------ | ------------------------------------------------------------------------------------------------------- | -------------------------- |
| brain  | In the `/host/pull` reply, in full on each pull, and after a push (`../hot-reload/README.md` HR6, HR9). | At once (HR18).            |
| hand   | The brain sets it on each `process.spawn` (`variables`, `environment-api/src/environment-api.ts:46`).   | At the next process start. |

A GitHub credential comes with `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME` and `GIT_COMMITTER_EMAIL` as plain values, so commits do not take the image's identity.

`shape` is for clients that check the key format. The placeholder then is `sk-ren-STRIPE_API_KEY`. `Credential.Env` (`schema/src/credential.ts:43`) gains `hosts` and `inject`, so that a skill or an app declares where its key may go.

### 6.6 Egress principal and registered keys

```ts
RegisteredKey = { id, kind: "egress" | "device", publicKey, orgs: "all" | OrganizationID[], revokedAt? }
```

1. Ren's own egress: `orgs: "all"`. Its adapter authenticates with mTLS. The client certificate holds the registered key. `EGRESS_TLS_CA` signs egress certificates only: any certificate it signs can resolve every workload's credentials.
2. A customer proxy: `orgs: [org_9]`. It calls `egress-api` with a 60 s assertion that it signs with its key (`private_key_jwt`, RFC 7523).
3. A device (laptop, phone) uses the same table for its hand. Section 7.
4. Delete the key to revoke. Nothing renews.

### 6.7 Signer (AWS KMS ready)

```ts
type Purpose = "brain" | "environment" // separate key sets (runtime decision E53)

interface Signer {
  readonly sign: (purpose: Purpose, claims: Schema.Json) => Effect<string, Signer.Unavailable>
  readonly publicKeys: (purpose: Purpose) => Effect<NonEmptyReadonlyArray<Signature.PublicKey>, Signer.Unavailable>
}
```

| Layer        | Keys                                                                                          | Signs with                                        |
| ------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `layerLocal` | `BRAIN_KEYS`, `ENVIRONMENT_KEYS` (`@ren/schema/signature`)                                    | the newest key                                    |
| `layerKms`   | `SIGNER_KMS_KEYS = { brain: [arn…], environment: [arn…] }`. Key spec `ECC_NIST_EDWARDS25519`. | KMS `Sign`, `ED25519_SHA_512`, `MessageType: RAW` |

1. KMS signs plain Ed25519. Brains check the same signatures with the same code. `layerKms` reads public keys with `GetPublicKey`.
2. The key id in each token is the key's `id` (local) or its ARN (KMS).
3. Rotation stays as runtime decision E45: add a key, let workloads get it in the pull, then sign with it.
4. `layerKms` keeps a signed token for its lifetime where it can (server token 5 min, client token 1 h), to stay under KMS request limits.
5. The two call sites that read private keys today use `Signer`: `core/src/brain-client.ts:45` and `core/src/environments.ts:99`.

### 6.8 Envelope (AWS KMS ready)

```ts
Sealed = { v: 1, keyId: string, wrappedKey: string, iv: string, ciphertext: string } // base64 fields
Context = { organizationId, kind: "credential" | "oauth_app" | "credential_caller", id }

interface Envelope {
  readonly seal: (value: Redacted, context: Context) => Effect<Sealed, Envelope.Unavailable>
  readonly open: (sealed: Sealed, context: Context) => Effect<Redacted, Envelope.Unavailable | Envelope.Tampered>
  readonly rewrap: (sealed: Sealed, context: Context) => Effect<Sealed, Envelope.Unavailable>
}
```

| Layer                 | Master key                                                   | Data key                                                                                                            |
| --------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `layerLocal`          | `ENVELOPE_KEYS = [{ id: "local:2026-10", key: <32 bytes> }]` | random per value; wrapped with AES-256-GCM                                                                          |
| `layerKms`            | `ENVELOPE_KMS_KEY = arn…`                                    | `GenerateDataKey` (`AES_256`); `Decrypt` with `EncryptionContext` = `Context`; plaintext data keys cached for 5 min |
| `layerMove(from, to)` | both                                                         | opens by the `keyId` prefix (`local:` or `kms:`); seals with `to`                                                   |

1. `ciphertext` is AES-256-GCM of the value with the data key. `Context` is the additional authenticated data. A value cannot move to another row.
2. A move to KMS changes `wrappedKey` only. A `DurableRunner` run `envelope-rewrap:<date>` calls `rewrap` on each row. Rows of both kinds can be read during the move.
3. Deployment secrets (Better Auth secret, database password, E2B API key) are not `Envelope` values. On AWS they go to AWS Secrets Manager.
4. The egress certificate authority (the key that signs the proxy's per-host certificates) stays a file for now. A KMS signer for it needs a fork change (`references/iron-proxy.md`).

### 6.9 Sign-in

1. Ren is a public OAuth client with dynamic registration, or uses an org's app or a built-in borrowed client (`Mcp.Auth.oauth.client`).
2. The one-time `state` is the authentication of the callback, because the provider's redirect carries no login cookie. Ren consumes `state` atomically. When the browser has a session, Ren also checks the owner rules.
3. The return address is fixed by Ren's config. A caller never supplies it. A built-in client's `redirectUri` is the one exception; a `127.0.0.1` redirect ends with the user pasting the callback address into the connect card.
4. Sign-in must return a refresh token (Google: `access_type=offline`, `prompt=consent`). A scope change marks the credential "Reconnect".
5. A sign-in over an existing credential keeps the old one valid until the new one is saved.
6. Renaming or archiving an org OAuth app that MCP servers use needs a confirmation that names them.
7. Edge rules (AWS WAF) must allow OAuth callback bodies (ren-v1 INV-107).

### 6.10 Egress process

1. The egress does not start without its CA, its hook address and its hook certificate (ren-v1 INV-89: a proxy with empty credentials looked healthy and refused all traffic for 2 days).
2. Its health check runs one real resolve through the hook.
3. Web search from OpenCode (Exa) and telemetry go through the egress with injected keys. No telemetry key goes into a workload (ren-v1 INV-91, OI-25).
4. In `HTTPS_PROXY` mode, `NO_PROXY` holds `localhost`, `127.0.0.1`, `0.0.0.0` and `::1`, so traffic to the brain's own hand and its own server stays local (ren-v1 INV-90).

## 8. Flows

| Flow        | Steps                                                                                                                                                                                                                             |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create      | `CredentialCallers.issue` → placement → `SandboxProvider.create` or `EnvironmentProvider.provision`. Ren writes the `credential_caller` row in the same step.                                                                     |
| Request     | workload → host adds proof → egress finds placeholders → `Egress.resolve` (cache 30 s) → inject → upstream.                                                                                                                       |
| Brain → Ren | The brain calls Ren at `REN_URL` with `Authorization: Bearer ren:REN`. The egress puts the host token in place of the placeholder; Ren's address changes through DNS. Ren checks the host token as today (runtime decision E50).  |
| Refresh     | Ren only. OAuth and LiteLLM keys: a single-flight sweep under a lease, before expiry (`references/ren-v1.md`). `REN`: signed again 20 min before `exp`. `Token` proof: Ren pushes a new one on `/ren/wake` and on the pull reply. |
| Replace     | New generation → new placement → revoke the old row. The old sandbox's proof fails at once (`generation_retired`).                                                                                                                |
| Leak        | Placeholder: useless outside the egress. `Token` proof: at most 1 h. Delivered secret: until someone rotates it.                                                                                                                  |

These use delivered secrets for now. The UI marks them. Only the owner of a credential can choose delivery. A delivered secret for a hand passes through its brain on `process.spawn`.

## 10. MCP and code mode

1. OpenCode makes MCP tools code-mode tools by default (`codemode: tool.codemode !== false`, `@opencode/core@2.0.27`). Ren never sets `codemode: false`.
2. A remote MCP server is configured with its real URL, `oauth: false`, and its placeholder header (`Authorization: Bearer ren:<LABEL>`). The placeholder is not a secret. The egress replaces it. One MCP can have several connections in one space, each with its own entry and label (`owner-access.md` A13, A14).
3. MCP settings are per Location, so per chat (`makeLocationNode`, `@opencode/core` MCP service). The Ren plugin installs them with `ctx.mcp.transform` and `ctx.mcp.reload()` as soon as a pull brings them (`../hot-reload/README.md` HR1).
4. A local (stdio) MCP server that needs a secret gets it as a delivered secret in `environment`.
5. The model provider in OpenCode always gets its real `baseURL` and a non-empty placeholder `apiKey` (ren-v1 INV-27, INV-28, OI-5).
6. A credential that a person connects during a chat works on the next request. The tools of a newly connected MCP server appear at a later step of the same turn, after the next pull (HR1). The pull before each prompt brings them at once.
7. Composio and other servers whose URL is the secret use `op: "route"`. OpenCode's config holds one placeholder URL per label (`https://composio.ren.internal/MCP_GMAIL`); the egress forwards to the real session URL of the credential that resolves, and adds the provider's account headers as `setHeader` ops (C36, `owner-access.md` A36). A Composio session URL is per person and per toolkit (ren-v1 `composio/index.ts`, `mintMcpUrl`).

## 11. Lifecycle states

| State                | What happens                                                                                                                                                                                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| asleep               | Nothing to renew in the workload. Ren keeps refreshing credentials.                                                                                                                                                                                            |
| waking               | The proof belongs to the sandbox, not to the process. `Token` proof: `/ren/wake` carries a new token first.                                                                                                                                                    |
| mid-turn             | Ren refreshes; the next request gets the new value. ren-v1's DS-T5 (MCP token expired mid-turn) cannot occur.                                                                                                                                                  |
| down (Ren)           | The egress answers from its cache: fresh for 30 s, then the last `allow` reply for up to 15 min (C37). Running turns keep their model, MCP and API calls. New labels, new workloads and denials wait for Ren. After 15 min, calls fail with `ren_unavailable`. |
| down (egress)        | The workload cannot reach Ren, the model or any API. The egress runs with more than one copy.                                                                                                                                                                  |
| restarting (process) | Nothing to reload. Placeholders are labels.                                                                                                                                                                                                                    |
| replaced             | Old proof revoked; old generation denied.                                                                                                                                                                                                                      |
| revoked              | A deleted credential, a removed member or an uninstalled app clears the cache at once. The next request is denied with a reason.                                                                                                                               |
