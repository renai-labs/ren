# Environments: decisions

Each row is one decision of [the environments spec](../README.md). Rows that a later row changes say so.

| ID   | Decision                                                                                                                                                                                                                                                                       | Why                                                                                                                                                                                                                                                                                                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EN1  | Ren's deployment sets the brain host and the brain image. Users configure environments only.                                                                                                                                                                                   | User decision; keeps e2b-brain E121. Every ren-v1 environment field (packages, build commands, CPU, memory, networking) describes where tools run, not the brain. The target is a brain host that Ren runs, with environments on E2B, later laptops and other sandboxes, and spaces with no environment.                                                                                 |
| EN2  | The brain and its environment share one sandbox only as a trait of today's E2B brain host. It is not a space setting.                                                                                                                                                          | User decision. The brain reaches tools only through the Environment API (`core/src/environments.ts:262-283`), so one sandbox or two is only the URL and token that `access` gives.                                                                                                                                                                                                       |
| EN3  | Packages, build commands, CPU and memory are in the E2B provider's `config`. The template schema keeps `provider` and `config`.                                                                                                                                                | User decision. They mean something only for a provider that builds an image; a laptop has its own. The provider's schema already checks `config` (`core/src/environment-provider.ts:84-89`).                                                                                                                                                                                             |
| EN4  | Up to `sessionsPerEnvironment` chats (default 8) share one environment. Chats share files across environments only through drives.                                                                                                                                             | User decision. One environment per space, as in ren-v1, puts every chat's load on one sandbox.                                                                                                                                                                                                                                                                                           |
| EN5  | The image builds when the template is saved, in one `DurableRunner` run per template and hash of the base image tag and the config.                                                                                                                                            | User decision; ren-v1 built at save (Temporal `EnvironmentBuildJob`). A build at the first chat makes that chat wait minutes. `DurableRunner` runs one execution per key across Ren replicas (`core/src/durable-runner.ts:8`).                                                                                                                                                           |
| EN6  | The template keeps the latest build only: `build_status`, `image`, `build_error`.                                                                                                                                                                                              | User decision. ren-v1's `environment_build` table with history and logs is one more table and API.                                                                                                                                                                                                                                                                                       |
| EN7  | While a build runs or after it fails, chats use the last `ready` image. A space cannot select a template that has never been built.                                                                                                                                            | User decision. ren-v1 used the preset until the custom build was ready (`api/src/sandbox/template-build.ts:24-31`).                                                                                                                                                                                                                                                                      |
| EN8  | `EnvironmentProvider` gets an optional `build(config) → image`.                                                                                                                                                                                                                | Core runs the build the same way for every provider; Docker can run `docker build`; a laptop has no build.                                                                                                                                                                                                                                                                               |
| EN9  | Ren keeps an environment awake: E2B `autoPause`, `keepAlive(30 min)` at each `access`, `keepAlive(10 min)` at `release` when no other seat is busy. `EnvironmentProvider` gets an optional `keepAlive`.                                                                        | User decision. Same pattern as the brain sandbox (`core/src/brain-lifecycle.ts:62-63`). The brain already calls `access` at the first tool call and at each token refresh, and `release` at turn end. Without the busy check, one chat's turn end would shorten another chat's running turn.                                                                                             |
| EN10 | An outdated environment is replaced at `access` when every seat on it is idle. Its chats lose their workspace files.                                                                                                                                                           | User decision; ren-v1 INV-16 moved a sandbox only when it was outdated and idle. Keeping chats on the old image means a package an admin adds never reaches existing chats.                                                                                                                                                                                                              |
| EN11 | Ren destroys an environment when every chat on it is archived, or when its template is archived.                                                                                                                                                                               | User decision. Today only a template archive destroys environments (`core/src/environment-templates.ts:223`), so paused environments accumulate.                                                                                                                                                                                                                                         |
| EN12 | A space has one choice, `space.environment`: `default`, a template, or `none`. The `SpaceEnvironmentTemplate` link table goes, and so does the per-chat picker of e2b-brain E20.                                                                                               | User decision. ren-v1 had one environment per team. Changes E20.                                                                                                                                                                                                                                                                                                                         |
| EN13 | `default` is Ren's standard environment, with the same meaning on every brain host. Today it is the brain's own sandbox.                                                                                                                                                       | User decision. Without it, "no template" means tools on the E2B brain host and no tools on a host without its own sandbox, so a host change would remove tools from every space without a template.                                                                                                                                                                                      |
| EN14 | `SessionRunner.create` resolves `space.environment` for every chat source.                                                                                                                                                                                                     | Five callers build `StartInput` today (`core/src/session.ts:337`, `task.ts:269`, `channels.ts:298` and `:405`, `schedules.ts:436`), and none sets an environment.                                                                                                                                                                                                                        |
| EN15 | When the space's choice changes, including to or from `none`, existing chats follow at their next idle point. Changed by EN24.                                                                                                                                                 | User decision; same rule as EN10.                                                                                                                                                                                                                                                                                                                                                        |
| EN16 | `networking` is a top-level template field. It can be `limited` only when the provider can limit hosts.                                                                                                                                                                        | User decision. Core makes the host list from Ren data (MCP servers, credentials), so core must read the field; core does not read a provider's `config`.                                                                                                                                                                                                                                 |
| EN17 | The provider enforces the host limit. E2B gets the list as `allowOut`. Ren's egress keeps only credentials. Changes the first proposal, a host check in `Egress.resolve`.                                                                                                      | User decision. E2B filters by HTTP `Host` and TLS SNI before traffic reaches the egress (E2B BYOP docs), so it also covers `tls.passthrough_hosts` such as ngrok, which the egress never decrypts. A check in the egress needs a fork change to cover them.                                                                                                                              |
| EN18 | The limit applies to the environment's traffic only. The brain's own web access follows the `webfetch` and `websearch` permission rules.                                                                                                                                       | User decision. A Durable Object brain has no egress, and the permission rules already exist.                                                                                                                                                                                                                                                                                             |
| EN19 | In `limited` mode the hosts of the space's credentials are always allowed.                                                                                                                                                                                                     | User decision. Otherwise `git push` to github.com fails after the person connected GitHub.                                                                                                                                                                                                                                                                                               |
| EN20 | Brain scope stays a space setting. Space members and org admins change it. Org admins get `space.update` on shared spaces.                                                                                                                                                     | User decision. Today only members can update a space (`core/src/space/policy.ts:44-46`).                                                                                                                                                                                                                                                                                                 |
| EN21 | A second harness is chosen per space; each chat keeps the harness it started with.                                                                                                                                                                                             | User decision. A space brain runs one harness process. Waits for harness-neutral sync (e2b-brain §3).                                                                                                                                                                                                                                                                                    |
| EN22 | Only org admins create and edit templates. Space members and org admins choose one for their space.                                                                                                                                                                            | User decision; today's policy (`core/src/environment-templates/policy.ts:20`). A template sets networking, which is a security limit for every space that uses it.                                                                                                                                                                                                                       |
| EN23 | After this spec: a spike for brains on ECS, in [`ecs-brain.md`](ecs-brain.md).                                                                                                                                                                                                 | User decision.                                                                                                                                                                                                                                                                                                                                                                           |
| EN24 | Existing chats follow a change between `default` and templates. A change to or from `none` applies to new chats only. Every environment uses `/home/user/workspace/<sessionId>`. Changes EN15.                                                                                 | User decision. The brain fixes a chat's folder and its tools when it creates the OpenCode chat (`cell/src/harness/opencode/harness.ts:88`, `:162`, `:174`), and Ren does not change OpenCode. The brain's own E2B sandbox already uses `/home/user/workspace` (`cell/e2b/start.sh:32`), and no production chat uses a template yet, so the template folder changes, not the brain's.     |
| EN25 | A save whose build key already finished runs the build once more outside `DurableRunner`. `build.run` gives the image of a tag it built before without building again. Ren also runs it at start for a template that stays `queued` or `building` after its run finished.      | A finished `DurableRunner` key never runs again (`core/src/durable-runner.ts:8`), so config A, then B, then A would leave the template `queued` with the image of B.                                                                                                                                                                                                                     |
| EN26 | A changed host list reaches a running environment at its next access: every `connect` sends the current list, and E2B `connect` resends the network. Not at the moment a credential or MCP server changes. Changes §3 Networking rule 6 (proposed; needs the user's approval). | `Credentials` and the MCP services cannot call `Environments` (it uses them for the list: an import cycle). Every access already calls `connect`, at most 10 min apart during a turn, and an update after `connect` never meets a paused sandbox: E2B answers 404 to a network update of a paused sandbox (checked live on 2026-11-05). So `EnvironmentProvider` has no `updateNetwork`. |
