# Brains, hands and machines: decisions

Each row is one decision of [the spec](../README.md). All are user decisions from the design review of 2026-11-06, unless the row says otherwise. They replace the decisions EN1–EN26 of the draft in PR #197.

## Model

| ID   | Decision                                                                                                                                                                                                                                         | Why                                                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EN1  | Two machine families: managed (Ren controls the machine's existence) and attached (Ren does not). Both meet one outer contract, `MachineAccess`: `ensure`, `access`, `release`, `status`, `retire`.                                              | What decides a machine's states is who controls its existence and how Ren reaches it, not the vendor. A laptop cannot be created, paused or replaced by Ren.           |
| EN2  | Brain providers and hand providers are two lists. The deployment registers them. A space picks one of each. The app hides the brain provider choice while the deployment has one.                                                                | Brain providers are few and each is built with the egress. Hand providers will be many.                                                                                |
| EN3  | A brain provider declares `canColocate`. A space's hand is co-located (with an optional template of the brain's provider), remote (a template of any hand provider), or none.                                                                    | Today's E2B brain is a co-located hand. Laptops, phones and other sandboxes are remote hands later.                                                                    |
| EN4  | In co-located mode the brain machine owns the one machine. The hand has no row.                                                                                                                                                                  | Two state machines for one machine can disagree.                                                                                                                       |
| EN5  | Managed brain machines and managed hand machines use one state machine, `MachineLifecycle`. Each gives its own ready check.                                                                                                                      | PR #197 made a remote hand inline in `Environments.access`, with no boot limit, failure count, `failed`, `capacity` or frozen check. One state machine is tested once. |
| EN6  | One managed provider contract replaces `SandboxProvider` and `EnvironmentProvider`: `create`, `connect`, `keepAlive`, `status`, `lastSample`, `list`, `destroy`, optional `build`, and flags. A step that a provider does not have does nothing. | `EnvironmentProvider` has no `status`, `lastSample`, `list` or `lost`, so Ren cannot see a dead, frozen or leaked hand.                                                |
| EN7  | An attached machine connects out to Ren, and Ren relays the Brain API and the Environment API. Its states and policies come later.                                                                                                               | A laptop or phone is behind NAT.                                                                                                                                       |
| EN8  | Transport is a seam: direct URL, `127.0.0.1`, or relay through Ren.                                                                                                                                                                              | `BrainClient.Target.url` (`core/src/brain-client.ts:15-22`) assumes a URL that Ren can reach.                                                                          |
| EN9  | Secrets mode is a seam: placeholders through the egress, real tokens, or none. This work builds placeholders.                                                                                                                                    | A machine outside the egress cannot get placeholders replaced (R19).                                                                                                   |
| EN10 | Ren's Postgres transcript owns resume. A harness's own checkpoints (such as Pi Durable) only speed up resume within one machine's life.                                                                                                          | A chat must move across machines and harnesses.                                                                                                                        |
| EN11 | One adapter per harness, with a hand bridge that connects the harness's tools to the Environment API. Core never imports harness code and never asks which vendor or harness it has.                                                             | Swap OpenCode for Pi without changes in core.                                                                                                                          |
| EN46 | The spec defines every seam. This work builds managed E2B machines only, co-located and remote.                                                                                                                                                  | Laptops, phones, Daytona and Pi come later on the same contracts.                                                                                                      |
| EN47 | A Durable Object brain is a managed machine.                                                                                                                                                                                                     | Ren manages it. Its provider has no pause and names the machine by id.                                                                                                 |

## Remote hands

| ID   | Decision                                                                                                                                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EN12 | Ren's server owns hand machines. Ren's OpenCode workspace driver stays thin: it asks Ren for `{ url, token }`.                                                                                               | OpenCode's `Workspace` (`opencode/packages/core/src/workspace.ts`) provisions once, connects lazily and suspends after 20 min idle. It has no health check and no replace. In the brain, the driver would need Ren's E2B key; its bindings live in OpenCode's SQLite, which sync does not copy (`brain/src/opencode-sync.ts:108-112`); a hand outlives one brain; the network list comes from Ren data; a dead brain cannot clean up. |
| EN13 | A brain that boots with `REN_HAND_PLACEMENT=remote` replaces OpenCode's `ToolOutput`, `FileSystem`, `Vcs` and `Snapshot` with versions that call the hand. A co-located brain keeps OpenCode's own services. | These four use the brain's disk and local git (`tool-output.ts:56-57`, `filesystem.ts:114-119`, `vcs.ts:261`, `snapshot.ts:77-96` in OpenCode). OpenCode's workerd profile turns them off (`server/src/workerd.ts:84-91`). A placement change always replaces the brain machine, so the choice at boot holds for the process's life. Fewer replacements mean less to match with upstream.                                             |
| EN14 | A co-located brain keeps the executor and today's three replacements (workspace driver, `rg`, `RenShell`).                                                                                                   | The executor gives the tools' memory cap (`cell/e2b/start.sh:32-42`), memory per process for the watchdog, tools that survive a brain restart, and moves between co-located and remote by a URL change.                                                                                                                                                                                                                               |
| EN15 | When the brain cannot reach its hand, it says so in its next `access`. Ren checks that machine.                                                                                                              | Today a running but unreachable hand fails every tool call until it pauses.                                                                                                                                                                                                                                                                                                                                                           |
| EN43 | Up to `sessionsPerEnvironment` chats (default 8) share one remote hand machine. A `release` while another chat on it is busy does not shorten the keep-alive.                                                | One machine per space puts all load on one sandbox. A shortened keep-alive pauses a machine mid tool call.                                                                                                                                                                                                                                                                                                                            |
| EN42 | Every hand uses `/home/user/workspace/<sessionId>`.                                                                                                                                                          | The brain fixes a chat's folder when it creates the chat (`cell/src/harness/opencode/harness.ts:167-180`), so a chat moves only between hands with the same folder.                                                                                                                                                                                                                                                                   |

## Detection and recovery

| ID   | Decision                                                                                                                                                                               | Why                                                                                                                                                                                                                                                                  |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EN16 | Ren checks a machine when a call to it fails and in the hourly cleanup. No sweeper.                                                                                                    | A sweeper is more code to keep. Listed under Later.                                                                                                                                                                                                                  |
| EN17 | A brain that gives no answer for 5 min, after `start.sh` restarted it, is replaced also when its machine runs.                                                                         | Today Ren keeps such a machine (`core/src/brain-lifecycle.ts:450-452`) while anyone keeps using it, because each access extends its keep-alive. Known risk: an outage of E2B's route from Ren to the brain makes Ren replace healthy brains. Covered by a chaos row. |
| EN18 | What counts as a failure stays as today: 3 failures of any kind, E2B errors included, give `failed`.                                                                                   | User decision. Known risk: an E2B outage of about 10 s during a boot gives `failed`. Covered by EN19 and a chaos row.                                                                                                                                                |
| EN19 | A `failed` machine starts again at its first access 10 min after the failure, then 30 min, then every hour. The Retry button stays. No timer (user decision in the build, 2026-11-06). | Without it, chats from schedules, tasks and channels on that brain stop until a person acts.                                                                                                                                                                         |
| EN20 | An unknown answer never destroys a machine (I11). Nothing is destroyed because a list does not show it (I12).                                                                          | A provider error is not proof that a machine is stale or dead. A paginated list is not a complete list.                                                                                                                                                              |
| EN35 | After a forced replace, every interrupted turn continues once, with a message that the machine was replaced and the files are gone.                                                    | Nothing else continues a chat that no person watches.                                                                                                                                                                                                                |
| EN36 | Right after a replace, Ren restores the chats that have waiting messages.                                                                                                              | A chat comes back only on its next request (`cell/src/restore.ts:23`).                                                                                                                                                                                               |
| EN38 | Ren sends a PostHog error report, with the reason, on `failed`, `capacity`, a forced replace and a failed build.                                                                       | An automatic stop that nobody hears about looks like a working system.                                                                                                                                                                                               |

## Changes

| ID   | Decision                                                                                                                                                                                                                                     | Why                                                                                                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EN21 | Every change reaches a machine when it wakes from sleep. No "Apply now".                                                                                                                                                                     | One code path (`resuming`). Nothing changes during a conversation. Waiting for an idle moment races with new turns.                                                           |
| EN22 | A template change that only adds packages or build commands installs on the machine in place at its wake. Other changes replace it.                                                                                                          | A replace loses the files. An install on the running machine reaches a busy machine without a swap.                                                                           |
| EN23 | Hand → none: the plugin refuses file and shell tools of existing chats at the next pull. None → hand: new chats only.                                                                                                                        | An admin may pick none to cut tool access. A chat created with no workspace link cannot get one, and running its tools in the brain process would skip the tools' memory cap. |
| EN24 | Archiving a template that a space uses is refused, with the spaces. A brain provider change that makes co-located impossible is refused until the space picks remote or none. Ren refuses to start when a provider in use is not registered. | A space never holds a setting that cannot run.                                                                                                                                |
| EN25 | While a chat has a process that still runs (a background shell), the machine stays awake, up to 2 h after the last turn's progress. The brain reports it in its pull (`PullSession.background`).                                             | Work that outlives a turn must keep its machine awake.                                                                                                                        |
| EN45 | Org admins get `space.update` on shared spaces. Space members and org admins change the hand, the brain provider and `brainScope`.                                                                                                           | Today only members can update a space (`core/src/space/policy.ts`).                                                                                                           |

## Images and bundles

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Why                                                                                                                                                                                                                                                                                     |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EN26 | Images hold the system and packages only. Ren's code ships as bundles that a machine pulls from Ren by hash: the dependencies (about 85 MB; their version is the hash of the installed tree, so it changes only when the machines' packages change: `bun.lock` changed 92 times in 30 days, user decision 2026-11-07) apart from the brain's and the executor's sources (about 0.2 MB), so a deploy sends little (user decision in the build, 2026-11-06). | Today the brain image's tag is a hash of the brain's and executor's sources (`cell/e2b/stage.ts:44-74`), and a brain on an older image is replaced at its wake (`brain-lifecycle.ts:280-284`). So each deploy wipes files, and with templates each deploy would rebuild every template. |
| EN27 | The brain and the executor have separate versions. A machine updates in place at its wake (`updating`): Ren calls `brain.update`, and the brain unpacks the bundles with `start.sh prepare` and restarts only the process that changed (user decision in the build, 2026-11-06). Three failed updates replace the machine.                                                                                                                                 | Background processes survive most deploys. E2B's process API stops a command after 60 s by default.                                                                                                                                                                                     |
| EN28 | When the OpenCode version changes in either direction, the brain flushes sync, deletes its local database, and restores from Postgres.                                                                                                                                                                                                                                                                                                                     | A rollback would make old code read a newer database.                                                                                                                                                                                                                                   |
| EN29 | The current bundle is one value per kind in Postgres that only moves forward.                                                                                                                                                                                                                                                                                                                                                                              | During a deploy, two servers could move a machine back and forth.                                                                                                                                                                                                                       |
| EN30 | One build at a time per template. A save during a build waits; the newest config builds next.                                                                                                                                                                                                                                                                                                                                                              | Parallel builds of one template waste builds and race. A build older than 45 min is reclaimed, so a crash mid-build never blocks the next one.                                                                                                                                          |
| EN44 | A template keeps its latest build only: `build_status`, `image` (last `ready`) and `build_error`. Machines use the last `ready` image. A space cannot pick a template that has never built.                                                                                                                                                                                                                                                                | Kept from PR #197. A build at the first chat would make that chat wait minutes.                                                                                                                                                                                                         |

## Networking

| ID   | Decision                                                                                                                                                                                                               | Why                                                                                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EN41 | `networking` is a template field. The provider enforces `limited` (E2B `allowOut`). The list always has the space's credential hosts. Every `connect` sends the current list. The egress keeps only credential checks. | Kept from PR #197. E2B checks Host and SNI before the egress, so hosts that the egress passes through without decryption are checked too. E2B refuses a network update of a paused sandbox. |
| EN40 | A co-located machine's `limited` list also has Ren's server, inference and egress hosts.                                                                                                                               | The brain runs on the same machine and needs them.                                                                                                                                          |

## Server and tests

| ID   | Decision                                                                                                                                                                                                                                          | Why                                                                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| EN31 | One Ren server, with a memory alarm and a load test (20 brains each syncing 8 MB at once).                                                                                                                                                        | `SingleRunner` is single-process (`repos/effect/packages/effect/src/cluster/SingleRunner.ts`). With one server, a server that runs out of memory stops everything. |
| EN32 | Environment tokens last 15 min. After Ren comes back, the next tool call gets a new token within 30 s. Accepted: tool calls fail after 15 min of Ren outage; machines pause after 30 min.                                                         | The renewal exists (`brain/src/environment/connections.ts:84-200`).                                                                                                |
| EN33 | Version N and N-1 work together in both directions: Ren and the brain, the brain and the executor.                                                                                                                                                | With bundles that only move forward, a brain can be newer than a server during a deploy.                                                                           |
| EN34 | Each managed machine carries labels (owner, kind, id, generation, organization, space). Each step finds its earlier work by kind, id and generation before it acts.                                                                               | E2B's brain `create` does this today (`core/src/sandbox-provider/e2b.ts:229-236`). A machine without labels cannot be found and cleaned up after a crash.          |
| EN37 | A message over the 8 MB sync limit syncs as a stand-in, and the chat keeps syncing.                                                                                                                                                               | Today one such message stops the chat's sync (`brain/src/opencode-sync.ts:202-206`). A sync that the server refuses forever loses its data when the machine goes.  |
| EN39 | Live tests run on the local `ren-stack` with real E2B and the real egress. Each pull request passes its own chaos rows; the full suite runs before the last merge. Seeded runs and a 1-hour soak. The user approves sandboxes once per suite run. | The lifecycles of machines, brains, Ren and the app act on each other. Only runs with the real parts show those effects.                                           |
