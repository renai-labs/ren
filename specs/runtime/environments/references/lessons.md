# Brains, hands and machines: lessons

Lessons from an earlier version of Ren that [the spec](../README.md) answers. Each one names the rule and the chaos row that cover it.

| #   | Lesson                                                                                                                                                  | In the spec                                                            | Chaos row  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------- |
| 1   | Never swap a busy machine for a new build. Swap it when it wakes.                                                                                       | EN21                                                                   | 23, 45     |
| 2   | A provider error is not proof that a machine is stale or dead.                                                                                          | I11                                                                    | 2, 42      |
| 3   | A resume that never confirms must end, not loop.                                                                                                        | Today: no wake and no answer → replace                                 | 4, 5       |
| 4   | E2B's connect resets the timeout to its 300 s default. Set the keep-alive again after each connect.                                                     | Today                                                                  | 46         |
| 5   | A keep-alive call must never shorten a longer window, or a machine pauses mid tool call.                                                                | Today; EN43                                                            | 32, 45     |
| 6   | E2B's process API stops a command after 60 s by default.                                                                                                | Ren runs no command through it; the brain runs the update (EN27)       | —          |
| 7   | A chat that was busy on a replaced machine must not stay busy.                                                                                          | Today: busy chats interrupted; EN35                                    | 3          |
| 8   | A crash between create and the row write leaks a machine unless the machine carries labels.                                                             | EN34                                                                   | 36, 52     |
| 9   | A paginated list is not a complete list. Never delete what a list does not show.                                                                        | I12                                                                    | 36         |
| 10  | A sync that the server refuses forever loses its data when the machine goes.                                                                            | EN37                                                                   | 10         |
| 11  | An old machine that survives its replace must not write over the new one.                                                                               | Today: Ren refuses a retired generation (`core/src/brains.ts:480-483`) | 48         |
| 12  | Parallel builds of one template race, and a crash mid-build must not block the next build.                                                              | EN30, EN44                                                             | 18, 21, 57 |
| 13  | Packages must reach a busy machine without waiting for a swap.                                                                                          | EN22                                                                   | 23         |
| 14  | Work that outlives a turn must keep its machine awake.                                                                                                  | EN25                                                                   | 45         |
| 15  | A restart decided on an idle moment can land on the next turn.                                                                                          | I13                                                                    | 49         |
| 16  | Waiters that hold database connections can stall the whole server.                                                                                      | Short transactions                                                     | 50         |
| 17  | One lock serializes every chat change in a brain (`brain-runtime/src/harness/opencode/harness.ts:533`), so a large restore delays sends in other chats. | Measure                                                                | 51         |
| 18  | A retry with no end turns a short blip into a long failure.                                                                                             | Lifecycle runs end in `failed`; EN19                                   | 1          |
| 19  | An automatic stop that nobody hears about looks like a working system.                                                                                  | EN38                                                                   | 1, 2       |
| 20  | With one server, a server that runs out of memory stops everything.                                                                                     | EN31                                                                   | 58         |
| 21  | A proxy's memory can grow until the system kills it.                                                                                                    | Later: egress memory alarm                                             | —          |
| 22  | A client clock ahead of the server can give duplicate replies.                                                                                          | Test                                                                   | 54         |
| 23  | A pending question must not stay pending after its machine is gone.                                                                                     | EN35                                                                   | 53         |
| 24  | Lost connections, a return to a tab, and new code after a deploy must not strand the app.                                                               | Test                                                                   | 55, 56     |
