# Channels: pending

A person mentions Ren in Slack, Linear or GitHub; Ren runs a turn in a space and answers in the same thread. GitHub steps 1 to 10 are built, and so are the Slack install, Sign in with Slack, Slack inbound and reply, the Slack MCP and Slack reactions.

Words: an **install** links a Ren organization to one provider workspace. A **place** is where people talk to Ren (a Slack channel, a Linear project, a GitHub repository). A **mapping** links a place to a space and an agent.

## 2. Decisions for these steps

| ID   | Decision                                                                                                                                                                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CH10 | Inbound files keep today's limit: 10 MB in total per message, as data URLs (`schema/src/session.ts:35`). A file over the limit is skipped, and the message text names it.                                                                                                              |
| CH11 | Sender to Ren user: an explicit account link wins. Otherwise email; Linear's comes from the webhook payload. The user must be a member of the install's organization.                                                                                                                  |
| CH19 | After a Slack install, the bot joins every public channel and sends the installer a welcome DM. No proactivity crons.                                                                                                                                                                  |
| CH21 | An install is a `channel_install` row plus an org-owned credential that holds its secret, sealed by `Envelope`. Linear's token refresh runs in the credential refresh sweep.                                                                                                           |
| CH23 | People who signed up another way connect from Settings → Channels (Add to Slack, Install GitHub App, Connect Linear), and from one optional onboarding step after sign-up.                                                                                                             |
| CH25 | Ren handles the uninstall events of each provider, Linear's revoke event included. Each removes the install, its credential and its mappings.                                                                                                                                          |
| CH40 | Ren shows progress in the provider, driven by session sync, not by the agent: a first sign at receipt (Linear "Working on it…" thought), the live Slack task card from the todo list, Linear thought and action activities, and an end marker. Linear needs an activity in about 10 s. |
| CH46 | Linear: Ren honours the `stop` signal (a new `brain.interrupt` in `BrainApi`, then a final activity), shows the todo list as the session's Agent Plan, sets `externalUrls` to the Ren session, and sends the `unlinked` refusal as an elicitation with the `auth` signal.              |
| CH47 | After a Slack install, the app opens v1's setup dialog: one row per unmapped public channel; each row maps the channel to an existing space, or creates a space named after the channel. A retry never creates a second space for one channel. The person can skip it.                 |
