# References: playbook

Status: spec written, not built. No Linear issue yet.

A reference is a git repository that an agent can read in a chat. This folder is the single source for references. Update this file in the same change that makes or changes a decision.

## 1. Goal

An agent reads the files of a public or private GitHub reference on every runtime that has an environment. This includes a brain in a Durable Object, which has no disk and no processes. No GitHub token reaches a brain or an environment.

This spec also fixes two GitHub problems near references (§11): an environment without an egress gets GitHub placeholders that do not work, and a skill from a private repository does not load.

Done when: the tests in §9 pass.

## 2. Problem

OpenCode clones a git reference with `git clone` into `<Global.repos>/<host>/<owner>/<repo>[@branch]`. `Git` and `RepositoryCache` are global nodes (`core/src/git.ts:1312`, `core/src/repository-cache.ts:233`), so the clone runs on the brain's machine. In a Ren chat, the read, glob, grep and shell tools run on the environment (`packages/cell/src/harness/opencode/workspace-driver.ts`). The model gets a path on the brain, but its tools look for the path on the environment.

| Brain host | Environment                | Clone runs on                                                                  | Tools find the files                 |
| ---------- | -------------------------- | ------------------------------------------------------------------------------ | ------------------------------------ |
| `e2b`      | Colocated hand (same disk) | Brain disk                                                                     | Yes, because the disk is shared      |
| `e2b`      | Docker template            | Brain disk                                                                     | No: `FileNotFoundError`              |
| `cell`     | Any                        | Nowhere. The spawner is `EnvironmentUnavailable` (`server/src/workerd.ts:79`). | No. The prompt still names the path. |

## 3. GitHub tokens in Ren today

This section describes built code. References use it and do not change it.

1. **Sources.** Two sources make a credential with the label `GITHUB` (`github-app.ts:31`):
   - The org's GitHub App installation. An org has at most one (`channel-installs.ts:174-178`). Ren mints an installation token when the egress needs it and does not store it (`credential-source.ts:217-229`). Owner: `org`. A repository outside the installation fails with the R11 404 message.
   - A person's GitHub sign-in. It is a `person` credential (`github-app.ts:283`). It resolves only in that person's private space (`../private-spaces/README.md`).
2. **Hosts.** `api.github.com`, `github.com`, `codeload.github.com`, `uploads.github.com` (`github-app.ts:278-281`).
3. **Placeholder, not the token.** The inject op is `replace` in headers (`credential-source.ts:227`). A workload holds only the text `ren:GITHUB`. The egress finds it, in plain form or inside `Basic`, and puts the real token in its place (`repos/iron-proxy/internal/ren/scan.go:37,138`).
4. **Lookup.** The egress finds a label in this order: workload, person, space, org. In a private space with a GitHub sign-in, the person's token wins. Otherwise the installation token applies.
5. **Variables.** Each pull gives the brain `GITHUB_TOKEN`, `GH_TOKEN` and a git `extraHeader`, all with the placeholder (`github-app.ts:308-329`, `core/src/brains.ts:499`). The brain gives them to every process that it starts on an environment (`packages/brain/src/environment/session.ts:69-73`).
6. **Where the egress replaces it.**

| Traffic from                       | Behind the egress?                                             |
| ---------------------------------- | -------------------------------------------------------------- |
| `e2b` brain and its colocated hand | Yes, when the provider can (`core/src/brain-lifecycle.ts:151`) |
| Docker template environment        | No. `core/src/environment-provider/docker.ts` has no egress.   |
| `cell` brain in a Durable Object   | No. The gateway Worker of credentials §7 is not built.         |

A placeholder that no egress replaces goes to GitHub as it is. GitHub answers 401 to it, also for a public repository.

## 4. Design

```
┌──────────────────────┐                                         ┌──────────────┐                                       ┌──────────────┐
│                      │   GET github.com/acme/docs.git/          │              │   same GET; ren:GITHUB replaced        │              │
│  brain               │   info/refs                              │  egress      │   by the real token                    │  github.com  │
│  (commit lookup)     │   1st: no Authorization                  │  (if any)    │  ────────────────────────────────►     │              │
│                      │   2nd: Basic x-access-token:ren:GITHUB   │              │  ◄────────────────────────────────     │              │
│                      │  ─────────────────────────────────────►  │              │   200: refs/heads/main = 9f3c2a1b…     │              │
└──────────────────────┘                                         └──────────────┘                                       └──────────────┘

┌──────────────────────┐                                         ┌──────────────────────┐
│                      │   reference.transform: type "local"      │                      │
│  Ren plugin          │   path=<root>/github.com/acme/docs/      │  OpenCode Reference  │
│                      │        9f3c2a1b7e4d                      │  (no clone)          │
│                      │  ─────────────────────────────────────►  │                      │
└──────────────────────┘                                         └──────────────────────┘

┌──────────────────────┐                                         ┌──────────────┐                                       ┌──────────────────────┐
│                      │   files.unpack {                         │              │   GET api.github.com/repos/acme/docs/  │                      │
│  brain               │    url: api.github.com/repos/acme/docs/  │  executor    │   tarball/9f3c…  (via the egress)      │  api.github.com      │
│  (before the first   │         tarball/9f3c…,                   │              │  ────────────────────────────────►     │  302 → codeload      │
│  environment tool)   │    headers: as the lookup that worked,   │              │  ◄────────────────────────────────     │  (temporary link)    │
│                      │    path: <root>/… }                      │              │   archive (.tar.gz)                    │                      │
│                      │  ─────────────────────────────────────►  │              │                                        │                      │
└──────────────────────┘                                         └──────────────┘                                       └──────────────────────┘
```

1. When the chat opens, the brain gets the commit of each reference from GitHub's ref list. It sends no `Authorization` first. If GitHub answers 401 or 404, it sends the request again with `Authorization: Basic base64(x-access-token:ren:GITHUB)`. This is the form git uses (`github-app.ts:327`).
2. The Ren plugin gives each reference to OpenCode as `type: "local"`, with the path `<root>/<host>/<owner>/<repo>/<first 12 characters of the commit>` and the description. OpenCode does not clone a local reference (`core/src/reference.ts:59`).
3. `<root>` is `.ren/references` in the parent folder of the chat folder. All chats on one environment use it. An environment belongs to one space and one template (`core/src/environments.ts:193-194`), so a root never holds files of another space.
4. Before the first environment tool of a chat, the brain calls `files.unpack` for each reference. The URL is `api.github.com/repos/<owner>/<repo>/tarball/<commit>`. The headers are the headers of the lookup that worked: none, or `Authorization: Bearer ren:GITHUB`. The executor downloads the archive itself and follows the 302. The bytes do not go through the brain.
5. The Ren plugin allows `external_directory` for `<root>/` on every host. It denies `edit`, `write` and `patch` for `<root>/`.
6. When the lookup of a reference fails, the Ren plugin does not give it to OpenCode. It adds one line to the system context: "The reference docs (acme/docs) is not available: <R11 cause>." (R14).

1. The picker lists the repositories of the org's GitHub installation (`GET /channel-places`). It does not show a repository that the space already has.
2. Without an installation, the picker is replaced by "Install the GitHub App to pick from your repositories", with a link to Settings → Channels → GitHub. The URL field stays, for public repositories.
3. A pasted URL is cleaned when the field loses focus: `/tree/<ref>` fills the branch; `/blob/…`, `/pulls`, `.git` and the query go away (ren-v1 `parseGitRepository`).
4. Each pick or URL adds one row. The alias is the repository name in lower case; a taken alias gets `-2`, `-3`. The person can change it. An alias has no slash, backslash, space, backtick or comma (`Reference.Alias`).
5. The description is required (R24). It starts with the GitHub description of the repository, when it has one.
6. Add sends one `PATCH /space-settings/{id}`. Ren runs R13 and R26 for each new reference. A refused reference shows its R11 message on its row, and nothing is saved.

### Edit dialog

Fields: Repository URL (cleaned as in step 3), Alias, Branch (empty: the default branch), Description (required). Save sends `PATCH /space-settings/{id}` with the same checks.

### Composer "+" menu

`+` → Repositories opens the Add repositories dialog for the chat's space. It changes the space settings, so every chat of the space gets the repository. A person who cannot update the space settings sees the item disabled, with "Only people who can change this space's settings can add repositories."

### Create space dialog

An optional Repositories section ("Optional · Ren reads a copy of these repositories") with an Add button that opens the same dialog. `Space.CreateInput` has no settings (`packages/schema/src/space.ts:66`), so Ren creates the space first, then sends `PATCH /space-settings/{id}`. If that save is refused, the space stays, and the Repositories tab opens with the R11 message.

### Changes to the session

Running brains get a change with the next push of settings. A chat that is open gets the repository at its next turn.

## 6. Words

| Word        | Meaning                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| Reference   | One `Reference.Info` entry in the settings of a chat: an alias, a repository, an optional branch and a description. |
| Root        | The folder on an environment that holds the files of all references: `<parent of the chat folder>/.ren/references`. |
| Generation  | The number that Ren gives an environment. A replaced environment has a new generation.                              |
| Placeholder | The text `ren:GITHUB`. The egress puts the real token in its place. Without an egress, it is not a credential.      |

## 7. Lifecycle

| State                                | What happens                                                                                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Brain asleep, then wakes             | The commit cache is empty. The brain looks up again. The same commit gives the same path, so nothing downloads.                                                                 |
| Brain restarts                       | As a wake.                                                                                                                                                                      |
| Branch moves during a turn           | The next lookup gives a new path. The old folder stays (R4). The model gets the change from OpenCode.                                                                           |
| GitHub App installed after the start | A failed lookup is tried again after 1 minute (R3). The retry sends the placeholder after the 401 or 404 (R9), and the egress now has the credential. No pull change is needed. |
| Environment does not answer          | `files.unpack` fails. The tool error says why and says to try again. The next environment tool tries again.                                                                     |
| Environment replaced                 | A new generation. The brain unpacks again (R5).                                                                                                                                 |
| Installation token expires (1 h)     | Ren mints a new one for the egress. The brain and the executor hold only the placeholder, so they do not see the change.                                                        |

## 11. GitHub near references

### 11.1 Environments without an egress

The brain gives every process on an environment the credential variables of its pull (`packages/brain/src/environment/session.ts:69-73`). For GitHub these are `GITHUB_TOKEN`, `GH_TOKEN` and a git `extraHeader` with `ren:GITHUB` (`github-app.ts:308-329`). A Docker environment has no egress (`core/src/environment-provider/docker.ts`), so the placeholder reaches GitHub as it is. `gh` and `git` then fail on the `cell-docker` profile as soon as the org installs the GitHub App.

Fix (R19): `Environment.Access` (`packages/schema/src/environment.ts:18`) gets `egress: boolean`. Ren sets it: the colocated hand has the egress of its brain; a template environment has the egress of its provider (Docker: none). The brain's spawner adds the credential variables only when `egress` is true. Private GitHub on a Docker environment then waits for egress for Docker environments.

### 11.2 Private skills

`SkillSource` reads the ref list from `github.com`, `SKILL.md` from `raw.githubusercontent.com` and the archive from `codeload.github.com`, with no `Authorization` (`packages/brain/src/skill/source.ts:13-17`). Fix: R20 and R21.
