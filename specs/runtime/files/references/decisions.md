# Files: decisions

Each row is one decision of [the files spec](../README.md). Rows that a later row changes say so.

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| F1  | Stores are needed. A file is a path in a store, not its own record.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | The environment disk is lost when a sandbox is replaced and has no owner. A mount, a prefix-scoped key and an access check each need one prefix, so a per-file record gives none of them.                                                                                                                                                                                                                                                                                                              |
| F2  | A chat upload or an agent output with no store named goes to a default store.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | User decision. ren-v1 had a default store per org and per user. Which default: topic 1.                                                                                                                                                                                                                                                                                                                                                                                                                |
| F3  | A store has one owner: a `space` or the `org`. There is no `person` owner. A person's own files are the stores of their private space (F6).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | User decision. v2 has no user groups. A `person` owner needs a rule for where it resolves; a private space is that rule as data. Replaces "`person`, `space` or `org`".                                                                                                                                                                                                                                                                                                                                |
| F4  | Each space has one default store. A chat upload or an agent output with no store named goes to the default store of the session's space. Org stores are created by a person; none is a default.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | User decision. The session's space is known for every session, so the upload always lands in a mounted store (F5).                                                                                                                                                                                                                                                                                                                                                                                     |
| F5  | A session sees the stores of its space and the stores of its org. Ren reads no membership and no brain scope for this.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | User decision. Every person who can open a session in a space can also open its stores. Membership changes do not mount or unmount anything. Replaces the "every active member can read" rule.                                                                                                                                                                                                                                                                                                         |
| F6  | A space is private when `space.user_id` is set, and shared when it is null. Ren sets it when it creates the space, and it never changes. `Space.Info` gives `isPrivate`, computed from `user_id`. Signup creates one private space per user.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | User decision. A member count is not a privacy fact: a shared space that people leave is still shared (user correction). A boolean with the owner in `space_member` allows invalid states (private with 0 or 2 members); one column does not. Prior art: ren-v1 `pod.user_id`.                                                                                                                                                                                                                         |
| F7  | In a private space: adding a member is refused; admins cannot get or create its sessions (`core/src/session/policy.ts:37` changes); when its user leaves the org, Ren archives the space, its stores and its credentials.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | User decision. The admin statement is `on: Policy.everywhere` today, so an admin could ask the agent of a private space to read its files.                                                                                                                                                                                                                                                                                                                                                             |
| F8  | Credentials move to the same model in their own PR: owners `workload`, `space`, `org`; a person credential becomes a credential of the person's private space. Until then, credentials keep `person`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | User decision. Credentials code already has `person` in offboarding, account sign-ins and the destination picker (`core/src/credentials.ts`).                                                                                                                                                                                                                                                                                                                                                          |
| F9  | A chat upload goes to the space drive at `chats/<sessionId>/uploads/<messageId>/<name>` (path changed by F11 and F14). The agent reads it on disk. The model also gets it inline when it is an image, text or PDF of 10 MB or less. Replaces the inline data URL in `Session.File` (`schema/src/session.ts:52`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | User decision. Same as ren-v1 (pod volume `session-files/<project>/<session>/uploads`), on the drive that already exists. The agent can use shell tools on any file type (ren-v1 INV-49), and the 10 MB per-message limit goes away.                                                                                                                                                                                                                                                                   |
| F10 | The agent shows a file with a `show_file {path}` tool. It copies the file to `chats/<sessionId>/outputs/<name>` in the space drive with a plain copy into the mount (changed by F17: it does not wait for S3). The tool part carries `{drivePath, name, mime, size}`. The transcript shows a card. A Files panel lists the uploads and outputs of the chat from the same message parts, with "Locate in chat".                                                                                                                                                                                                                                                                                                                                                                                                                | User decision. Same as ren-v1: `show_file` (`opencode-plugin/src/tools/show-file.ts`) and the `SessionArtifacts` panel, built from messages. The panel was deleted in `bff47807f` and only the cards came back (`f916c69e8`, REN-1293). The mount uploads after 5 s (`executor/src/sandbox/drives.ts:140`), so a plain copy gives a 404 on an early Download.                                                                                                                                          |
| F11 | `Session.Prompt.files` carries drive paths in the session's space drive, not `data:` URLs. At send, the server checks each path with HEAD. It reads an image, a text file or a PDF of 10 MB or less from S3 and sends it to the brain inline as today. For every other file, it adds a line with the file's path to the prompt text. The prompt metadata keeps `{path, name, mime, size}` for each file, so the transcript and the Files panel show the drive file after a reload.                                                                                                                                                                                                                                                                                                                                            | User decision. One rule for the app, the SDK and Slack (ren-v1 bug `df6e6f39a`). The brain has no S3 keys, and the mount can be up to 10 s late (`--dir-cache-time 10s`, `executor/src/sandbox/drives.ts:147`). OpenCode reads only `data:` and `file:` URIs (`opencode core/src/session/prompt.ts:95,155`) and silently drops any type other than text, image or PDF (`to-llm-message.ts:83`).                                                                                                        |
| F12 | The channel workflow writes each Slack file to `chats/<sessionId>/uploads/<messageId>/<name>` in the space drive with `Drives.put`. `Drives.put` is a server write with no actor check, and a retry writes the same key. The prompt then takes the F11 path. Each Slack file is at most 32 MiB. The Slack `upload_file` tool takes `content` (text) or `path` (a drive file); for `path`, the server reads the file from S3 and uploads it to Slack.                                                                                                                                                                                                                                                                                                                                                                          | User decision. Today a Slack file is base64, 10 MB at most (`channel-provider/slack.ts:329`, `channels.ts:83`), so a zip never reaches the agent. 32 MiB is ren-v1's channel limit (`0939ea45c`). `upload_file` takes only `content: string` (`slack-bot.ts:308`), so the agent cannot post a PNG or a PDF.                                                                                                                                                                                            |
| F13 | No drive page in the app for now. The app gets drives only through the chat: the attach button and file paste in the composer, file cards, and the Files panel (F10). Every org member can still read and write the org drive (`core/src/drives/policy.ts:21`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | User decision. The API and the CLI already list, upload, download and delete. ren-v1 store pages were deleted in `bff47807f`.                                                                                                                                                                                                                                                                                                                                                                          |
| F14 | Composer: a person attaches a file from the plus menu ("Upload attachment", F15), by paste or by drop. The draft gets `messageId` at the first attach, and send uses it. Each file uploads at once with `drive.startUpload` to `chats/<sessionId>/uploads/<messageId>/<name>` and shows an `Attachment` chip (`uploading`, `error` with Retry and Remove, `done`). The draft keeps the `done` chips as `{path, name, mime, size}`; a reload drops chips that are still uploading. Limits: 100 MiB per file, checked before the upload, and 10 files per message. Send is disabled while a chip is `uploading` or `error`. Removing a `done` chip deletes the file and does not wait. Attaching works while a turn runs.                                                                                                       | User decision. The composer refuses files today (`session-composer.tsx:636`). A new chat's session ID is known before send (`new-chat.tsx:37`), but a message ID is made at send (`new-chat.tsx:123`). ren-v1 REN-1220: attach while running.                                                                                                                                                                                                                                                          |
| F15 | The UX matches ren-v1. The plus menu shows "Upload attachment" as its first item, in a group of its own, above Mention and Repositories. A user message gets `uploads: SessionMessage.DriveFile[]` (`{path, name, mime, size}`) from `metadata.files`. Clients get no base64; the OpenCode row keeps it. One card for uploads and `show_file` outputs, with a thumbnail or an icon, the name, the size, a click that opens the viewer, and Download. The card gets its link from `drive.download` when it scrolls into view, and fetches a new one once on a load error. A 404 shows "Deleted from the drive". A message from before F11 renders its files from `data`. An old chat that is opened again shows every file, and after a new sandbox the agent still reads them from the drive. No S3 versioning, as in ren-v1. | User decision ("exactly like v1", screenshot of the v1 menu). ren-v1 REN-1277 (`af82a8fcf`): files in reloaded chats, and a fallback card when a file is gone. ren-v1 kept chat files on the pod volume, which survived a new sandbox (`06-vm-files.md`).                                                                                                                                                                                                                                              |
| F16 | The viewer follows OpenCode (`~/Documents/opencode/packages/gui-extensions/src/{file,microsoft-office}`), rewritten in React. PDF: the browser's own viewer in a frame, which needs a link without `Content-Disposition: attachment`. HTML: a sandboxed frame. DOCX, XLSX and PPTX: `@betteroffice/*` in a worker, loaded only when a file of that type opens. CSV and TSV: a table. Markdown, code and text: shiki. Images, audio and video: native. Everything else: name, type, size and Download. Every viewer has Download. A file with a generic MIME type gets its type from the extension. The Files panel is the same as ren-v1's: a right sheet opened from the chat header, filters All, Documents, Images, Code and Links with counts, date groups, and Locate in chat.                                           | User decision. The standard is to render in the browser: Open WebUI, Onyx, LobeHub and OpenCode all do. ren-v1 sent the signed link to the Google Docs viewer (`office-viewer.tsx`), and used `xlsx` 0.18.5 (CVE-2023-30533, CVE-2024-22363). `@betteroffice` is Apache-2.0, version 0.5.x.                                                                                                                                                                                                            |
| F17 | Every remaining choice copies ren-v1. `show_file` is a plain copy into the mount, as in ren-v1 (`show-file.ts`). Mounts get ren-v1's two fixes, which the v2 executor lacks (`executor/src/sandbox/drives.ts`): upload pending writes before the sandbox stops (INV-75, `cd76ce4bb`), and remount after the sandbox resumes from pause (INV-76, `3308ca40a`). A chat with no environment gets inline files only. The spec says "drive", as the code does.                                                                                                                                                                                                                                                                                                                                                                     | User decision: this is a port of a ren-v1 feature, not a new design.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| F18 | On E2B, inline files reach OpenCode as `file://` paths on the rclone mount, not as bytes read by the server. The server checks each path with HEAD and passes `{path, name, mime, size}`; the brain chooses file content or a path note, and refreshes the upload folder in rclone before the prompt. Chats on a cell are out of scope for now. Changes F11.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | User decision: "on E2B it is rclone; cells are fixed separately". The brain and its tools share one E2B sandbox (`../e2b-brain/README.md:3`), which mounts drives (`core/src/sandbox-provider/e2b.ts:170`).                                                                                                                                                                                                                                                                                            |
| F19 | The Files panel lists files only: uploads and `show_file` outputs, filters All, Documents, Images, Code. No Links tab. Changes F10 and F16.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| F20 | CSV and TSV preview: OpenCode's `parseDelimited` (`gui-extensions/src/file/artifact.ts:23`), run in a worker, first 1,000 rows, with ren-v1's grid (fixed-width columns, pinned header and row numbers). No SheetJS. Changes F16.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | User decision. ren-v1 parsed the whole file on the main thread with no cap (`csv-viewer.tsx`), and wide sheets rendered blank until `0af1fbc80`.                                                                                                                                                                                                                                                                                                                                                       |
| F21 | Drop, paste and picker keep ren-v1's edge cases (`use-composer-attachments.ts`, `composer-attachments.ts`): react only to `Files` drags, count drag enter and leave, stop the browser from opening a dropped file, fall back to `items[].getAsFile()` on paste, reset the picker after each pick, take the MIME type from the extension when it is generic. Files still upload at attach (F14), not at send as in ren-v1.                                                                                                                                                                                                                                                                                                                                                                                                     | User decision ("drag and drop worked properly").                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| F22 | The mount uploads a file when it is closed (`--vfs-write-back 0s`), not 5 s later. There is no drain at stop. After a pause, the mount is kept as it is: no health check and no remount. Each rclone serves its control interface on a unix socket, and `drives.refresh {path}` makes the mount list a folder again. Changes F17.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | User decision, from measurements on rclone v1.75.2. E2B stops a sandbox with no signal ("shutdown the sandbox immediately"). With a 5 s write-back, a write 1 s before a SIGTERM, an unmount or a SIGKILL was lost; with 0 s, a 1 MB write 0.3 s before a SIGKILL was in S3. On E2B, after a pause of 2 min, the same rclone processes served the first read, both from S3 in the sandbox and from AWS. A health check would also replace a slow rclone, which `drives.slow.test.ts` keeps on purpose. |
