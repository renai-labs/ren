# Webhooks: decisions

Each row is one decision of [the webhooks spec](../README.md). "User decision" means that the user chose it. "Proposed" means that the spec set it before the user discussed it.

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| W1  | Changed by W26. A webhook is not a channel and does not use `ChannelProvider`. It copies the shape of a schedule: space, owner, agent, message, a row for each run, and a pause reason.                                                                                                                                                                                                                                                                                                                                                                                  | A webhook has no reply and no sender identity. Of the 19 members of `ChannelProvider`, a webhook could use only `verify` and `parse` (`core/src/channel-provider.ts:75`); the others install, reply, find places and find senders. A schedule already has `space_id`, `owner_id`, `agent_id`, `schedule_run` and `paused_reason`.                                                                                                                                                    |
| W2  | A person creates a webhook in a chat, where Ren writes the parser, or with a form in settings.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| W3  | A webhook created in a chat gets the space, the person and the agent of that chat. Settings can change each.                                                                                                                                                                                                                                                                                                                                                                                                                                                             | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| W4  | After the test request, the person tells Ren "done", and Ren reads the deliveries. The webhook keeps no link to the chat that created it.                                                                                                                                                                                                                                                                                                                                                                                                                                | User decision. No webhook-to-chat link is needed.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| W5  | Changed by W25. The parser is data (`when`, `deliveryId`, `threadKey`, `title`), not code. The agent reads the raw payload.                                                                                                                                                                                                                                                                                                                                                                                                                                              | User decision. Inngest and Hookdeck run JavaScript transforms because their action needs a fixed input. The action of Ren is a model that reads JSON. Only the filter, the key and the duplicate check must run before the model. Code needs a sandbox on the server.                                                                                                                                                                                                                |
| W6  | Replaced by W25. Paths use dots and array indexes. "Any item of a list" is not possible; the agent checks it in the chat.                                                                                                                                                                                                                                                                                                                                                                                                                                                | User decision. A person fills in a path in a form.                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| W7  | Replaced by W25. All conditions of `when` must match. Ren checks them in order and gives the first one that fails as the `reason`.                                                                                                                                                                                                                                                                                                                                                                                                                                       | Proposed. One reason for each delivery is enough to fix a parser. The order lets the event type filter out other shapes first (W21).                                                                                                                                                                                                                                                                                                                                                 |
| W8  | A webhook is `listening` or `live`. A person and Ren can switch it both ways at any time. A new webhook is listening.                                                                                                                                                                                                                                                                                                                                                                                                                                                    | User decision. Listening gives a real request to build and test the parser on, and keeps requests while the parser is broken.                                                                                                                                                                                                                                                                                                                                                        |
| W9  | Two tables, `webhook` and `webhook_delivery`. Their columns copy `schedule` and `schedule_run` where they mean the same.                                                                                                                                                                                                                                                                                                                                                                                                                                                 | User decision. Same shape as schedules (`db/src/schedule.sql.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                   |
| W10 | The owner is the last person who changed `message`, `rule` or `agent_id`. A switch to live after `owner_left` makes the switcher the owner. Other switches keep the owner.                                                                                                                                                                                                                                                                                                                                                                                               | User decision. Same as schedules (`core/src/schedules.ts:692`, `:730`). Nobody can make chats run as another person. A channel mapping lets the editor pick any member (`core/src/channel-mappings.ts:223`); that was refused for webhooks.                                                                                                                                                                                                                                          |
| W11 | Every member of the space can do everything with its webhooks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | User decision. Same as schedules (`core/src/schedule/policy.ts:17`).                                                                                                                                                                                                                                                                                                                                                                                                                 |
| W12 | A body is at most 1 MB. A `rejected` delivery keeps headers only. Retention deletes a delivery after 30 days.                                                                                                                                                                                                                                                                                                                                                                                                                                                            | User decision. A stranger cannot fill the table. 30 days is the retention of schedule runs (`core/src/retention.ts:16`).                                                                                                                                                                                                                                                                                                                                                             |
| W13 | The model gets a header made from the metadata of the message, with a note that the request is data from outside Ren. Headers omit `authorization`, `cookie` and the `verify` header.                                                                                                                                                                                                                                                                                                                                                                                    | User decision. Same pattern as the channel header (`cell/src/harness/opencode/plugin.ts:162`). Anyone who can cause the event writes part of the prompt, and the chat runs with the credentials of the owner.                                                                                                                                                                                                                                                                        |
| W14 | A body of 16 KB or less is in the message. A larger body is `payload.json` in the space drive.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | User decision. A PostHog event is about 3 KB; a GitHub pull request event is 20 to 40 KB. Channels attach files the same way (`core/src/channels.ts:139`).                                                                                                                                                                                                                                                                                                                           |
| W15 | A delivery for a chat in a turn waits in the queue.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | User decision. Same as a schedule with a target chat (`core/src/schedules.ts:425`). Channels steer (`core/src/channels.ts:427`).                                                                                                                                                                                                                                                                                                                                                     |
| W16 | The URL token and the signing secret are sealed with `Envelope` on the `webhook` row. They are not credentials.                                                                                                                                                                                                                                                                                                                                                                                                                                                          | User decision. Ren gives credentials to the environments of agents (`db/src/credential.sql.ts:100`). `channel_install.secret` uses the same sealed column (`db/src/channel.sql.ts:27`).                                                                                                                                                                                                                                                                                              |
| W17 | The URL, with its token, shows in settings and in the chat. `rotateUrl` replaces the token.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | User decision. Ren gives the URL in the chat, so the person needs no settings page. The token is then in the transcript of the chat. A signing secret is the real proof of the sender when the provider signs.                                                                                                                                                                                                                                                                       |
| W18 | Only settings sets or shows the signing secret. Its endpoints have `Mcp.Hidden`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | User decision. The model never sees a value that proves the sender.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| W19 | `verify` has 5 kinds: `none`, `header`, `hmac`, `standard`, `stripe`. Ren picks the kind from the docs of the provider.                                                                                                                                                                                                                                                                                                                                                                                                                                                  | User decision. These 5 cover GitHub, Sentry, Linear, PostHog, Stripe and the providers on Standard Webhooks (Svix, Clerk, Resend).                                                                                                                                                                                                                                                                                                                                                   |
| W20 | While listening, a delivery with no signing secret set is `recorded` with `verified: false`. A webhook goes live only with a signing secret if `verify` needs one.                                                                                                                                                                                                                                                                                                                                                                                                       | User decision. Stripe shows its secret only after it has the URL, so the first test request arrives before the secret.                                                                                                                                                                                                                                                                                                                                                               |
| W21 | 5 broken deliveries in a row switch a live webhook to listening with `parser_broken`. Broken: a missing path in `when`, `deliveryId` or `threadKey`, or a wrong signature. Changed by W25 and W36: broken is a CEL error in `handshake`, `filter`, `deliveryId` or `threadKey`. A wrong signature is not broken.                                                                                                                                                                                                                                                         | User decision. Same as the `failing` pause of schedules after 5 failed runs (`schema/src/schedule.ts:96`). A value that is not in `is` is normal filtering.                                                                                                                                                                                                                                                                                                                          |
| W22 | On `parser_broken`, Ren starts one repair chat in the space, as the owner. No second one starts until the webhook changes.                                                                                                                                                                                                                                                                                                                                                                                                                                               | User decision. A repair that fails does not start a loop.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| W23 | After a repair, Ren replays the `recorded` deliveries with the new parser. Each delivery starts at most one chat.                                                                                                                                                                                                                                                                                                                                                                                                                                                        | User decision. No request is lost while the parser is broken.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| W24 | `deploy.yaml` has no webhook secret. `webhooks.yaml` has no mode: apply creates a webhook as listening, and the mode is live state.                                                                                                                                                                                                                                                                                                                                                                                                                                      | First part: user decision (W16). Second part: user decision. The spec wins at apply (`../../../infra.md`, section 1, rule 3), so a declared mode would undo each switch to listening by Ren.                                                                                                                                                                                                                                                                                         |
| W25 | The parser fields `filter`, `deliveryId`, `threadKey` and `title` are CEL expressions, evaluated with `@bufbuild/cel`. `false` is ignored; an error is broken. The form writes simple CEL. Replaces W6 and W7.                                                                                                                                                                                                                                                                                                                                                           | User decision. CEL is the standard for expressions that untrusted authors write: Tekton, Kubernetes and Envoy use it. It has no I/O and always ends, so it runs in the server with no sandbox. It tests lists (`exists`), which paths cannot. `false && <error>` is `false`, so a filter that checks the event type first does not call other shapes broken. `@bufbuild/cel` is maintained by Buf, 1.1M downloads in the week before 2026-11-06. See [`prior-art.md`](prior-art.md). |
| W26 | One Intake path for every source. A source gives intake, route, prompt and report; Intake owns the durable job, the duplicate check, the thread and the start of the chat. Build it from `Channels` first, with no behaviour change, then add webhooks. Changes W1.                                                                                                                                                                                                                                                                                                      | User decision. Tekton and Argo Events put built-in sources and generic webhooks into one pipeline. Without it, webhooks copy the job, the duplicate check, the thread and the chat start of `core/src/channels.ts`.                                                                                                                                                                                                                                                                  |
| W27 | Reversed: schedules are not a source of Intake. The clock starts them, and they already use `DurableRunner` and `SessionRunner`, the two parts that Intake would share with them. Before: Schedules are a source of Intake. Their clock is the intake; `Schedules` keeps timing and pause reasons. Retries: W30.                                                                                                                                                                                                                                                         | User decision, then reversed by the user: Intake would only add `deadlineOf` and `targetSessionId` for schedules and a refactor of `core/src/schedules.ts`. A schedule run starts or continues a chat as an owner on an agent (`core/src/schedules.ts:413`), which is the same as a webhook delivery.                                                                                                                                                                                |
| W28 | `channel_thread` becomes `intake_thread`, keyed by `(kind, scope, key)`. The channel columns stay, and are null for other sources. A webhook finds its chat there, not through its delivery rows.                                                                                                                                                                                                                                                                                                                                                                        | User decision. One thread table for every source. Changes section 5 of the first version of this spec, which found the chat through `webhook_delivery`.                                                                                                                                                                                                                                                                                                                              |
| W29 | A source is a record of Effect functions in `Intake.Sources`, a layer that collects them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | User decision. Intake picks the source for each request; a Layer is picked once at start. Same pattern as `ChannelProvider.layer` (`core/src/channel-provider.ts:116`).                                                                                                                                                                                                                                                                                                              |
| W30 | Changed by W27: only webhooks give a deadline (W46). Before: `Intake.Run` tries a refused or failed run again until the `retryUntil` of its source. Schedules give the next fire, or 1 hour for a one-time run. Channels and webhooks give none.                                                                                                                                                                                                                                                                                                                         | User decision. One retry mechanism in Intake. Same times as today (`core/src/schedules.ts:461`).                                                                                                                                                                                                                                                                                                                                                                                     |
| W31 | At most 60 requests a minute for each webhook. Over the limit, Ren answers 429 and saves the delivery with its body as `throttled`. It starts no chat. `replay` can start it later.                                                                                                                                                                                                                                                                                                                                                                                      | User decision. GitHub does not send a failed delivery again by itself, so a `throttled` delivery keeps it.                                                                                                                                                                                                                                                                                                                                                                           |
| W32 | `body` is a map for `application/json` and `application/x-www-form-urlencoded`, and the text for every other type.                                                                                                                                                                                                                                                                                                                                                                                                                                                       | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| W33 | A `handshake` CEL field answers handshakes. `GET` requests reach the URL. Its order with the signature check: W38.                                                                                                                                                                                                                                                                                                                                                                                                                                                       | User decision. Microsoft Graph, Dropbox and Zoom send a challenge before the first event.                                                                                                                                                                                                                                                                                                                                                                                            |
| W34 | Each CEL expression has at most 1,000 characters.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | User decision. The user also chose the cost limit of the evaluator, but `@bufbuild/cel` has none (checked in its source, 2026-11-06). The CPU bound: W37.                                                                                                                                                                                                                                                                                                                            |
| W35 | The repair chat runs on the default agent of the space.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | User decision.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| W36 | A wrong signature does not count as broken.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | User decision. Else a person with the URL can switch a live webhook to listening with 5 requests.                                                                                                                                                                                                                                                                                                                                                                                    |
| W37 | Ren adds no cost limit to CEL. The bounds are: 1,000 characters for each expression, a body of at most 1 MB, and the signature check before CEL.                                                                                                                                                                                                                                                                                                                                                                                                                         | User decision. CEL is not Turing-complete, so every evaluation ends. Kubernetes adds a runtime cost budget for evaluations that end but take long (kubernetes.io/docs/reference/using-api/cel, "Resource constraints"); no JavaScript CEL library has one. Only a signed request, or one with the URL of a `verify: none` webhook, can cause a long evaluation.                                                                                                                      |
| W38 | Two handshake fields. `handshake` runs before the signature check and has no `sign`. `signedHandshake` runs after it and has `sign(text)`, the hex HMAC-SHA256 with the signing secret.                                                                                                                                                                                                                                                                                                                                                                                  | User decision. Microsoft Graph and Dropbox do not sign their challenge; Zoom signs it and wants an HMAC of `plainToken`. A `sign` before the signature check gives a person with the URL the HMAC of any text, which forges the signature of any body.                                                                                                                                                                                                                               |
| W39 | Webhooks are listed only in a space tab, Space → Webhooks. There is no org page.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | User decision. A webhook belongs to one space and has no install. Schedules have an org page; webhooks are fewer.                                                                                                                                                                                                                                                                                                                                                                    |
| W40 | A webhook has its own page with two tabs, Setup and Deliveries. Create uses a right sheet, as schedules do.                                                                                                                                                                                                                                                                                                                                                                                                                                                              | User decision. A sheet has no room for the request viewer and the parser.                                                                                                                                                                                                                                                                                                                                                                                                            |
| W41 | The parser shows as rows (path, operator, value) that write CEL, with "Edit as CEL" for the rest. A click on a value of a delivery adds a row.                                                                                                                                                                                                                                                                                                                                                                                                                           | User decision. A person builds a parser with no knowledge of paths or CEL.                                                                                                                                                                                                                                                                                                                                                                                                           |
| W42 | A webhook message shows a marker ("Webhook · name · time · View request") and the request as a collapsed card.                                                                                                                                                                                                                                                                                                                                                                                                                                                           | User decision. Same kind of marker as schedules (`app/src/features/session/transcript.tsx:375`).                                                                                                                                                                                                                                                                                                                                                                                     |
| W43 | An HTTP source gives one `receive(request)`, which answers `Answer` or `Start`. Verify, parse and the side effects of the source stay in it.                                                                                                                                                                                                                                                                                                                                                                                                                             | User decision. Slack signals, uninstall, delivery rows and handshakes are not Intake concerns. Intake does not branch on parse results that only one source has.                                                                                                                                                                                                                                                                                                                     |
| W44 | Each source has its own event type and schema. Intake keeps the event as JSON and does not read it. Replaces a shared `Intake.Event` made from `Channel.Event`.                                                                                                                                                                                                                                                                                                                                                                                                          | User decision. A shared type makes Intake depend on the fields of every source.                                                                                                                                                                                                                                                                                                                                                                                                      |
| W45 | The repair chat is a `Start` of the webhook source, `{ _tag: "repair", webhookId }`, with the key `repair:<webhookId>:<updated_at>`.                                                                                                                                                                                                                                                                                                                                                                                                                                     | User decision. A source that calls Intake makes a cycle. The key gives one repair chat for each version of the webhook.                                                                                                                                                                                                                                                                                                                                                              |
| W46 | A webhook run that fails tries again until `received_at` + 1 hour.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | User decision. Without it, a brain that is down loses the delivery. Same window as a one-time schedule (`core/src/schedules.ts:461`).                                                                                                                                                                                                                                                                                                                                                |
| W47 | Names are nouns for services and data, one word for each meaning, and names in their context: `Intake` (not `Inbound`), `origin: Session.Origin` (not `kind`), `Intake.Sources`, `Intake.Run`, `IntakeThreads`, `Intake.start`, `receive` and `Received`, `resolve`, `keyOf`, `promptOf`, `deadlineOf`, `senderUserId`, `requiresAgent`, `targetSessionId`, `ChannelIntake.source` and `WebhookIntake.source`, `signature`, `WebhookSignature.verify`, column `parser`, `handshake` and `signedHandshake`, outcome `answered`, and `eventId` for the ID of the provider. | User decision. Nouns for services and data, one word for one meaning, names in their context. `Session.Origin` and `Channel.Event.eventId` already exist with these meanings.                                                                                                                                                                                                                                                                                                        |
